Roadmap

Flint UI's goal: a mini design system in the spirit of Material Design 2 — a small, opinionated set of flat, Google-flavored app shells and components, backed by a docs site that makes each piece copy-pasteable.

Guiding principles

  • Docs ship with every component. A component without a docs page is not done. A docs page without a component is a lie.
  • The docs site is built with Flint. Docs needs (breadcrumbs, callouts, code blocks, sidebar) become real component requirements, not guesses.
  • Zero dependencies, forever. No build step for users; copy two files and go. Docs tooling must not leak into the library.
  • Flat, 1px borders, no shadows — the Material 2019–2020 look — is the design constraint that keeps the library small and coherent.
  • Distribution is copy-paste (the shadcn model): the docs' core feature is a copy button on every snippet.

Sequencing rule

Build the docs shell thin, then never add a component without its page. Docs without components is an empty shell; components without docs are a pile of CSS.

Where this docs site stands

The five shipping components (bottom-nav, rail, drawer, auth, lists) have full pages. Buttons and cards already exist in the library as 0.1 building blocks and get their full pages next; dialog and bottom sheet are honest stubs marked Planned · 0.4 until the overlay work lands — the sidebar only ever links somewhere real.
