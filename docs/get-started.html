Get started

Flint UI is two files — flint.css (~800 lines) and flint.js (~50 lines). No build step, no dependencies, no webfonts. Copy them in and use the classes.

Quick start

Grab the two files from the repo and link them — the script is deferred and tiny, so order doesn't matter:

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

Then pick a shell and paste its markup — every component page's Implementation tab has a copy-paste-ready starting point, and demos/*.html in the repo are full working pages.

Pick a shell

All three app shells share the same parts — top bar, content column, nav — and switch layout at 905px with pure CSS:

ShellPhones≥905pxPick when
Bottom-nav Bottom tab bar Centered pill bar 3–5 destinations, mobile-primary
Rail Bottom tab bar 80px icon rail 3–5 icon-shaped destinations, desktop-first feel
Drawer Off-canvas drawer + scrim Permanent 280px nav column Many destinations, app-like product
Auth Centered card (no breakpoint flip) Sign-in and pre-app screens (zero JS)

Selection: aria-current="page"

One attribute drives every selected state — nav rows, tabs, list rows all key off aria-current="page". With flint.js loaded, clicking inside any data-fl-nav container moves it automatically (anchors still navigate). Without JS, set it yourself — which is what you want with server routing anyway:

<nav class="fl-tab-bar" data-fl-nav aria-label="Primary">
  <button class="fl-tab" aria-current="page">…</button>  <!-- selected -->
  <button class="fl-tab">…</button>
</nav>

Works without JS

Everything renders correctly with JavaScript disabled. flint.js only adds two conveniences:

  • Selected-state reflection on click (with server routing you set aria-current yourself).
  • Drawer toggling — the open/close buttons and scrim work through it. Without JS, control the drawer by toggling fl-drawer-open on <body> yourself, or call flint.drawer(true/false).

Icons are empty placeholder squares (a fl-icon span renders a gray block) — swap in any real icon set without touching other markup; sizes are fixed by the surrounding component classes.

Tokens

The whole look is ~30 CSS custom properties on :root in flint.css. The essentials:

TokenDefaultRole
--fl-accent#1a73e8Selection, links, focus, filled buttons
--fl-tint#e8f0feSelected-state fills (pills, rows)
--fl-border#dadce0Every border — replaces every shadow
--fl-fontsystem-uiOS default — no webfont; override to brand
--fl-radius / --fl-radius-card4px / 8pxCorner radii
--fl-topbar-h64px (56px <600px)Top bar height
--fl-content-max960pxDesktop reading column
--fl-dur / --fl-ease150msMotion

Override inline or in your own stylesheet — no rebuild:

:root {
  --fl-accent: #188038;    /* green Google */
  --fl-tint: #e6f4ea;
}

Each component page's Theming section lists the tokens it actually consumes.
