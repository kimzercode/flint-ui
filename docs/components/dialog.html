Dialog

Four dialog types on the native <dialog> — focus, Escape, scrim and stacking come from the platform; flint.js only wires triggers and the non-dismissible opt-out.

Usage

A dialog interrupts the flow to demand a decision or a short piece of input. It is the most expensive surface in an interface — everything on screen goes inert behind it — so it must be the only thing the user can act on while open.

Do use it for

  • Destructive confirmations — "Delete conversation?" with Cancel and a danger action.
  • Short forms — rename, invite, move-to; a single field plus actions. Enter submits via method="dialog".
  • Decisions that block the flow — unsaved-changes warnings before navigation.

Don't use it for

  • Non-blocking feedback — "Message sent" is a snackbar, not a dialog; never make the user click an OK to dismiss good news.
  • Long or exploratory content — release notes, settings, browsing. That is the bottom sheet or a normal page; dialogs cap at ~88vh for a reason.
  • Chaining decisions — a wizard behind three OKs is a page, badly compressed.

The hard parts are platform work — by design

showModal() provides the focus trap, the inert background, Escape-to-close and top-layer stacking natively. Flint deliberately ships no custom focus management: the classic hand-rolled overlay is 300 lines of fragile JS. flint.js only wires data-fl-open / data-fl-close and returns focus to the invoker on every close path. Open and close animations are pure CSS (@starting-style + allow-discrete).

Field family

Types

Material 2 defines four dialog types. Flint ships them as one surface plus three modifiers — the differences are content and layout, not separate components.

TypeShapeUse it for
Alert Title + body + actions (the default, no modifier) One decision that blocks the flow — "Delete conversation?", unsaved-changes warnings
Simple Title + vertical option list (fl-dialog__list + fl-dialog__option); picking a row closes with that row's value Choosing from a small set without a form — "Apply label", pick an account
Confirmation Question title + dismissive/confirming pair; when the decision needs a choice, radio/checkbox rows in the list and the confirm stays disabled until one is made "Filter by priority?" — decide, then confirm
Full-screen fl-dialog--fullscreen + fl-dialog__header (close, title, confirming action in the top bar); body scrolls The mobile form pattern — compose, settings sub-pages; content too big for a card

Rule of thumb: one decision → alert; pick one of N → simple; choose then confirm → confirmation; the content is a real form → full-screen (or a bottom sheet, when it isn't destructive).

Anatomy

  1. Surface — the card vocabulary: --fl-radius-card, 1px border, 24px padding. Flex column; long bodies scroll inside while title and actions stay pinned.
  2. Title — the headline size (24px/400), wired with aria-labelledby.
  3. Body — supporting text, or a field for form dialogs.
  4. Actions — right-aligned; Cancel as a text button, the confirm as filled — or fl-btn--danger (--fl-error) for destructive confirms.

Actions

  • Order: the dismissive action sits left of the confirming action — keep that DOM order; it is also the tab order and the visual order.
  • Acknowledgment carries one action. An alert that only informs gets a single OK / Got it — no decorative Cancel beside it.
  • Confirm only when a choice exists. In confirmation dialogs with radio/checkbox rows, keep the confirming action disabled until a choice is made — one change listener in author code (snippet below).
  • Stacked actions: long labels or narrow surfaces get fl-dialog__actions--stacked — full-width buttons with the confirming action above the dismissive one. DOM order is unchanged (dismiss first, confirm second); the modifier reverses the visual order.
  • Buttons: Cancel is a text button, the confirm is filled, and destructive confirms are fl-btn--danger.

Dismissal

By default a dialog closes on Escape and on a scrim click — flint.js wires both, and focus returns to the invoker on every close path. Some dialogs must be answered: an unsaved-changes warning whose only options are "Keep" and "Discard" makes no sense to dismiss by tapping the void.

Add data-fl-dismissible="false" to the <dialog> and both dismissal paths are refused (Escape via the native cancel event, scrim clicks in the wiring), while explicit actions keep working — data-fl-close buttons and method="dialog" submits are unaffected.

Use it sparingly. A dialog the user cannot leave must still offer a safe way out — a Cancel/Keep action — or it is a trap. Non-dismissible is for decisions, never for information.

Behavior

  • Markup contract: any element with data-fl-open="dialog-id" opens it; data-fl-close inside the dialog closes it; or close it yourself with flint.dialog.close(el) / el.close().
  • Cancel/confirm results are free: put the actions in <form method="dialog"> — submitting closes the dialog and records the pressed button's value in dialog.returnValue. Read it after close; no extra JS. Buttons outside the form can still submit it with the form attribute.
  • Focus: moves to the first focusable control on open; returns to the invoker on every close path (button, Escape, scrim click, submit).
  • Dismissal: Escape and scrim clicks both close — unless the dialog opts out with data-fl-dismissible="false" (see Dismissal).
  • Stacking: a dialog can open over a bottom sheet (or another dialog) — the top layer stacks them in DOM order and Escape peels only the top one.
  • Scroll lock: the page locks while any overlay is open, restored on close.
  • Animation: 150ms fade + scale in, slide/scale out, scrim fading on the same clock — all CSS, prefers-reduced-motion disables it entirely.
  • No-JS fallback (honest): without flint.js the dialog stays hidden and the page keeps working — the content is not lost, it just can't be opened. Call showModal() yourself with one line, or drive it from your own code; the CSS has no JS dependencies. See the overlay infra demo for the raw lifecycle.

Accessibility

  • Give the dialog aria-labelledby pointing at its title — the screen reader announces the dialog by name.
  • The inert background is native: nothing behind the dialog is focusable, clickable or announced. No aria-hidden is juggled on the page — the classic bug doesn't exist here.
  • Focus starts on the first control (usually Cancel — the safe choice) and cycles within the dialog. Keep Cancel first in the DOM.
  • fl-btn--danger uses --fl-error (#d93025, 4.9:1 on white — AA for its 14px/500 text).
  • Don't remove the focus ring; the global :focus-visible ring is what makes the trap visible to keyboard users.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

Destructive confirm — actions in method="dialog" forms:

<button class="fl-btn fl-btn--outline" data-fl-open="dlg-delete">Delete conversation</button>

<dialog class="fl-dialog" id="dlg-delete" aria-labelledby="dlg-delete-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-delete-t">Delete conversation?</h2>
    <p class="fl-dialog__body">
      This conversation will move to the trash. You can restore it for 30 days.
    </p>
    <div class="fl-dialog__actions">
      <form method="dialog"><button class="fl-btn fl-btn--text" value="cancel">Cancel</button></form>
      <form method="dialog"><button class="fl-btn fl-btn--danger" value="delete">Delete</button></form>
    </div>
  </div>
</dialog>

Form dialog — a field family body; Enter submits, Save submits from the actions row via form="rename-form":

<dialog class="fl-dialog" id="dlg-rename" aria-labelledby="dlg-rename-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-rename-t">Rename label</h2>
    <form class="fl-dialog__body" method="dialog" id="rename-form">
      <label class="fl-field">
        <span class="fl-field__label">Label name</span>
        <input class="fl-field__input" value="Finance">
      </label>
    </form>
    <div class="fl-dialog__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
      <button class="fl-btn fl-btn--filled" form="rename-form" value="save">Save</button>
    </div>
  </div>
</dialog>

Reading the result — zero extra plumbing:

document.querySelector("#dlg-rename").addEventListener("close", () => {
  const decision = document.querySelector("#dlg-rename").returnValue; // "save" | ""
});

Simple dialog — one method="dialog" form wraps the option list; every row is a submit button, so picking one closes and records its value. Rows are fl-dialog__option (48px, hover state layer, optional leading icon — you supply the SVG):

<dialog class="fl-dialog" id="dlg-label" aria-labelledby="dlg-label-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-label-t">Apply label</h2>
    <div class="fl-dialog__list">
      <form method="dialog">
        <button class="fl-dialog__option" value="finance">
          <svg width="18" height="18" viewBox="0 0 24 24"><!-- your icon --></svg>
          Finance
        </button>
      </form>
      <form method="dialog">
        <button class="fl-dialog__option" value="personal">Personal</button>
      </form>
    </div>
    <div class="fl-dialog__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
    </div>
  </div>
</dialog>

Confirmation — the confirming action stays disabled until a choice exists (author code, one listener):

<dialog class="fl-dialog" id="dlg-filter" aria-labelledby="dlg-filter-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-filter-t">Filter by priority?</h2>
    <form class="fl-dialog__body" method="dialog" id="filter-form">
      <div class="fl-dialog__list">
        <label class="fl-dialog__option">
          <input type="radio" name="prio" class="fl-radio" value="high"> High priority
        </label>
        <label class="fl-dialog__option">
          <input type="radio" name="prio" class="fl-radio" value="normal"> Normal
        </label>
      </div>
    </form>
    <div class="fl-dialog__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
      <button class="fl-btn fl-btn--filled" id="filter-confirm"
              form="filter-form" value="filter" disabled>Filter</button>
    </div>
  </div>
</dialog>

<script>
  // author code — enable the confirm once the required choice exists
  document.getElementById("dlg-filter").addEventListener("change", function () {
    document.getElementById("filter-confirm").disabled = false;
  });
</script>

Full-screen — the mobile form pattern; the confirming action lives in the header, the body scrolls beneath it:

<dialog class="fl-dialog fl-dialog--fullscreen" id="compose" aria-labelledby="compose-t">
  <div class="fl-dialog__surface">
    <div class="fl-dialog__header">
      <button class="fl-icon-btn" data-fl-close aria-label="Close">
        <svg width="20" height="20" viewBox="0 0 24 24"><!-- X icon --></svg>
      </button>
      <h2 class="fl-dialog__title" id="compose-t">New message</h2>
      <button class="fl-btn fl-btn--filled" form="compose-form" value="send">Send</button>
    </div>
    <form class="fl-dialog__body" method="dialog" id="compose-form">
      <!-- fl-field fields — the body scrolls, the header stays pinned -->
    </form>
  </div>
</dialog>

Non-dismissible with stacked actions — the user must choose; long labels stack full-width with the confirming action on top:

<dialog class="fl-dialog" id="unsaved" data-fl-dismissible="false" aria-labelledby="unsaved-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="unsaved-t">Discard this draft?</h2>
    <p class="fl-dialog__body">Your reply hasn't been sent yet.</p>
    <div class="fl-dialog__actions fl-dialog__actions--stacked">
      <form method="dialog"><button class="fl-btn fl-btn--text" value="keep">Keep editing</button></form>
      <form method="dialog"><button class="fl-btn fl-btn--danger" value="discard">Discard the draft permanently</button></form>
    </div>
  </div>
</dialog>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-scrimThe backdrop, shared with the bottom sheet and drawer
--fl-surfaceThe card fill
--fl-borderThe 1px card border
--fl-radius-cardCorner radius (8px)
--fl-errorThe danger action
--fl-dur / --fl-easeOpen/close animation timing
 
:root {
  --fl-scrim: rgb(0 0 0 / 0.4);   /* darker scrim, every overlay follows */
  --fl-radius-card: 4px;          /* squarer dialogs */
}
