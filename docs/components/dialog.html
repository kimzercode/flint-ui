Dialog

The native <dialog> wearing Flint's card — focus, Escape, scrim and stacking come from the platform; flint.js only wires the triggers.

Usage

A dialog interrupts the flow to demand a decision or a short piece of input. It is the most expensive surface in an interface — everything on screen goes inert behind it — so it must be the only thing the user can act on while open.

Do use it for

  • Destructive confirmations — "Delete conversation?" with Cancel and a danger action.
  • Short forms — rename, invite, move-to; a single field plus actions. Enter submits via method="dialog".
  • Decisions that block the flow — unsaved-changes warnings before navigation.

Don't use it for

  • Non-blocking feedback — "Message sent" is a snackbar, not a dialog; never make the user click an OK to dismiss good news.
  • Long or exploratory content — release notes, settings, browsing. That is the bottom sheet or a normal page; dialogs cap at ~88vh for a reason.
  • Chaining decisions — a wizard behind three OKs is a page, badly compressed.

The hard parts are platform work — by design

showModal() provides the focus trap, the inert background, Escape-to-close and top-layer stacking natively. Flint deliberately ships no custom focus management: the classic hand-rolled overlay is 300 lines of fragile JS. flint.js only wires data-fl-open / data-fl-close and returns focus to the invoker on every close path. Open and close animations are pure CSS (@starting-style + allow-discrete).

Field family

Anatomy

  1. Surface — the card vocabulary: --fl-radius-card, 1px border, 24px padding. Flex column; long bodies scroll inside while title and actions stay pinned.
  2. Title — the headline size (24px/400), wired with aria-labelledby.
  3. Body — supporting text, or a field for form dialogs.
  4. Actions — right-aligned; Cancel as a text button, the confirm as filled — or fl-btn--danger (--fl-error) for destructive confirms.

Behavior

  • Markup contract: any element with data-fl-open="dialog-id" opens it; data-fl-close inside the dialog closes it; or close it yourself with flint.dialog.close(el) / el.close().
  • Cancel/confirm results are free: put the actions in <form method="dialog"> — submitting closes the dialog and records the pressed button's value in dialog.returnValue. Read it after close; no extra JS. Buttons outside the form can still submit it with the form attribute.
  • Focus: moves to the first focusable control on open; returns to the invoker on every close path (button, Escape, scrim click, submit).
  • Dismissal: Escape and scrim clicks both close. If a dialog must not be dismissible (unsaved changes), that is an author decision: prevent the native cancel event and hide data-fl-close.
  • Stacking: a dialog can open over a bottom sheet (or another dialog) — the top layer stacks them in DOM order and Escape peels only the top one.
  • Scroll lock: the page locks while any overlay is open, restored on close.
  • Animation: 150ms fade + scale in, slide/scale out, scrim fading on the same clock — all CSS, prefers-reduced-motion disables it entirely.
  • No-JS fallback (honest): without flint.js the dialog stays hidden and the page keeps working — the content is not lost, it just can't be opened. Call showModal() yourself with one line, or drive it from your own code; the CSS has no JS dependencies. See the overlay infra demo for the raw lifecycle.

Accessibility

  • Give the dialog aria-labelledby pointing at its title — the screen reader announces the dialog by name.
  • The inert background is native: nothing behind the dialog is focusable, clickable or announced. No aria-hidden is juggled on the page — the classic bug doesn't exist here.
  • Focus starts on the first control (usually Cancel — the safe choice) and cycles within the dialog. Keep Cancel first in the DOM.
  • fl-btn--danger uses --fl-error (#d93025, 4.9:1 on white — AA for its 14px/500 text).
  • Don't remove the focus ring; the global :focus-visible ring is what makes the trap visible to keyboard users.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

Destructive confirm — actions in method="dialog" forms:

<button class="fl-btn fl-btn--outline" data-fl-open="dlg-delete">Delete conversation</button>

<dialog class="fl-dialog" id="dlg-delete" aria-labelledby="dlg-delete-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-delete-t">Delete conversation?</h2>
    <p class="fl-dialog__body">
      This conversation will move to the trash. You can restore it for 30 days.
    </p>
    <div class="fl-dialog__actions">
      <form method="dialog"><button class="fl-btn fl-btn--text" value="cancel">Cancel</button></form>
      <form method="dialog"><button class="fl-btn fl-btn--danger" value="delete">Delete</button></form>
    </div>
  </div>
</dialog>

Form dialog — a field family body; Enter submits, Save submits from the actions row via form="rename-form":

<dialog class="fl-dialog" id="dlg-rename" aria-labelledby="dlg-rename-t">
  <div class="fl-dialog__surface">
    <h2 class="fl-dialog__title" id="dlg-rename-t">Rename label</h2>
    <form class="fl-dialog__body" method="dialog" id="rename-form">
      <label class="fl-field">
        <span class="fl-field__label">Label name</span>
        <input class="fl-field__input" value="Finance">
      </label>
    </form>
    <div class="fl-dialog__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
      <button class="fl-btn fl-btn--filled" form="rename-form" value="save">Save</button>
    </div>
  </div>
</dialog>

Reading the result — zero extra plumbing:

document.querySelector("#dlg-rename").addEventListener("close", () => {
  const decision = document.querySelector("#dlg-rename").returnValue; // "save" | ""
});

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-scrimThe backdrop, shared with the bottom sheet and drawer
--fl-surfaceThe card fill
--fl-borderThe 1px card border
--fl-radius-cardCorner radius (8px)
--fl-errorThe danger action
--fl-dur / --fl-easeOpen/close animation timing
 
:root {
  --fl-scrim: rgb(0 0 0 / 0.4);   /* darker scrim, every overlay follows */
  --fl-radius-card: 4px;          /* squarer dialogs */
}
