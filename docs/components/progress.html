Progress

Determinate and indeterminate progress in two shapes — a restyled native element and a conic-gradient ring. Zero JavaScript.

Usage

Progress shows that work is happening and, when you can, how far along it is. Pick the shape by context:

ShapeUse for
LinearIn-flow waits tied to content — uploads, loading a list, a multi-step form
CircleStandalone waits — page transitions, connecting states, spots too tight for a bar

Determinate vs indeterminate

  • Determinate whenever the fraction is knowable — a progress bar that moves honestly beats a spinner that guesses.
  • Indeterminate when duration is unknown — do not animate a fake percent toward an invented 100%.

M2's consistency rules

  • One type per activity — if a refresh shows a circle on one screen, the same action never shows a bar elsewhere.
  • Sequences show overall progress — a multi-step process gets one indicator of the whole, not one per step.
  • Never decorative — an indicator that doesn't reflect a real process is noise; take it out.
  • In buttons: rare and short — a spinner inside an action is for short indeterminate waits (2–5s: "Connecting…"). Don't attach progress to every button; and for longer waits, let a snackbar or notification carry the outcome instead.

The state lives in the platform, not in classes

Linear progress is the native <progress> element: value/max IS the state and :indeterminate (no value attribute) is the platform's own switch. The circle is a div — its state is one custom property, --fl-progress-value.

Pair it with a snackbar

A common pairing: an indeterminate spinner while connecting, then a determinate bar for the transfer, then a snackbar to confirm — three honest states, no invented numbers.

Anatomy

  1. Track — the tint (--fl-tint), 4px thick, 2px radius on the linear bar.
  2. Fill — the accent (--fl-accent); width is the native value for linear, the arc is --fl-progress-value for the circle.
  3. Circle ring — 4px stroke cut out of a conic-gradient disc with a mask; sized by --fl-progress-size (48px default, M2's circular spec). M2's circular track is invisible; Flint paints a faint tint ring so the scale reads at a glance — hide it per element with style="--fl-tint: transparent" for the strict M2 look.

Behavior

  • Zero JavaScript — the component ships no script at all. flint.js isn't involved; the page below runs with JS off entirely (the demo's only script is the author demo moving the value).
  • Linear determinate: set value/max — the native attributes. Moving the value moves the fill; the width change eases over --fl-dur.
  • Linear indeterminate: remove the value attribute — :indeterminate swaps in a bar that grows and shrinks while sweeping the track (M2's choreography, one bar instead of two; 1.2s loop).
  • Circle determinate: set --fl-progress-value: 0–100 (inline or from your JS). The ring is a conic-gradient — no JS library, no SVG arc math.
  • Circle indeterminate: add the is-indeterminate class — a 270° accent arc rotates (0.9s loop). M2's arc also grows and shrinks as it travels; Flint keeps a fixed arc — the same 2020-era idiom, one less moving part.
  • Sizing: --fl-progress-size scales the circle (stroke stays 4px); the linear bar is 4px tall and full-width of its container.
  • Reduced motion: the sweep stops and the bar parks at center; the spinning circle stops as a static 270° arc — state stays readable without the animation.

Accessibility

  • Linear: the native <progress> element is already a progressbar — just add aria-label. Don't add role; the platform has it.
  • Circle: a plain div knows nothing — give it role="progressbar", aria-valuemin/max/now (determinate) or aria-label alone (indeterminate), and update aria-valuenow when --fl-progress-value changes.
  • Label the process, not the widget — "Uploading files", not "Progress".
  • Indeterminate is announced as such by both shapes — no fake percentages, matching the no-fake-100% rule above.
  • Contrast: the accent (#1a73e8) on the tint (#e8f0fe) track reads as a state indicator, not text — the honest pairing M2 uses; nearby text should carry the actual numbers.

Code

<link rel="stylesheet" href="css/flint.css">

No script tag needed — this component is CSS only.

Linear — determinate; the native attributes are the whole API:

<progress class="fl-progress" value="35" max="100"
          aria-label="Uploading files"></progress>

Linear — indeterminate: drop the value attribute:

<progress class="fl-progress" aria-label="Loading feed"></progress>

Circle — determinate: the value is one custom property:

<div class="fl-progress-circle" style="--fl-progress-value: 60" role="progressbar"
     aria-valuemin="0" aria-valuemax="100" aria-valuenow="60"
     aria-label="Backing up"></div>

Circle — indeterminate: one class:

<div class="fl-progress-circle is-indeterminate" role="progressbar"
     aria-label="Connecting"></div>

Moving it from your JS (linear and circle):

// linear: the native element is the state
bar.value = percent;

// circle: the property is the state — keep aria-valuenow in step
ring.style.setProperty("--fl-progress-value", percent);
ring.setAttribute("aria-valuenow", percent);

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-accentThe fill / arc
--fl-tintThe track / ring background
--fl-progress-valueThe circle's determinate state (0–100, per element)
--fl-progress-sizeThe circle's diameter (per element)
--fl-dur / --fl-easeFill easing and loop timing
 
:root {
  --fl-accent: #0b8043;   /* a green progress, Google-2020 green 600 */
  --fl-tint: #ceead6;     /* its matching track tint */
}
