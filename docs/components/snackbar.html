Snackbar

Low-priority status feedback on the inverse surface — never modal, one at a time, gone on its own.

Usage

A snackbar confirms that a process the user started has completed — minimal interruption, optional action, zero demanded attention. It is the lowest-priority member of the feedback family:

ComponentPriorityUser action
SnackbarLowOptional — disappears by itself
Bottom sheetMediumOptional — a choice, dismissible
DialogHighestRequired — blocks the page until answered

Do use it for

  • Process confirmations — "Conversation saved", "Message sent", "Address copied".
  • Amendable outcomes — an Undo action is the classic snackbar move: the process happened, and here's a 4s window to reverse it.

Don't use it for

  • Anything that needs a decision — that's a dialog.
  • Errors that need context or recovery — a snackbar can't hold an explanation; use a dialog or inline field errors.
  • Dismiss buttons — M2 is explicit: a dismiss action is unnecessary because snackbars disappear on their own. Flint still wires data-fl-close inside a snackbar, but don't build UIs around it.
  • Icons — the message is the content; if it needs an icon, it's a different component.

Flat by identity — no elevation

M2 asks for a shadow under the snackbar container; we deliberately ship none. The inverse surface (near-black on light content) provides the separation, matching the flat Google look of the 2020 era. Like every token: --fl-text is the container, --fl-surface is the label.

Feedback family

Anatomy

  1. Text label — one line (two on mobile), directly related to the process performed. No icons.
  2. Container — opaque inverse surface, 4px radius, 48px min-height; docked 8px from the bottom edge. No shadow (see the callout above).
  3. Action — optional, exactly one: a text button in the bright accent (--fl-accent-inverse), never filled, never the label's color.

Behavior

  • Markup contract: any element with data-fl-open="snackbar-id" shows it; flint.js adds is-visible and starts the timer. Or drive it yourself: flint.snackbar.show(el) / flint.snackbar.hide(el) — the class is plain CSS.
  • Auto-dismiss: 4 seconds, then it leaves on its own. Re-triggering the same snackbar restarts the clock.
  • One at a time (M2): showing a second snackbar hides the first — they replace, never stack.
  • Non-modal: the page stays fully interactive — no focus trap, no scroll lock, no inert background. The snackbar never takes focus.
  • Placement: docked to the bottom edge, one gutter token (--fl-snackbar-inset, 8px plus the safe-area inset), above FABs (z-layer --fl-z-snackbar). In wide layouts it is left-anchored and capped at 560px — pick one alignment and keep it consistent everywhere (M2 forbids mixing).
  • FABs are not covered: flint.css lifts a .fl-fab by 56px while a snackbar is visible (body:has(.fl-snackbar.is-visible) .fl-fab) — the two never stack and no measurement is involved. Author CSS that docks something else at the bottom edge should do the same.
  • Above persistent navigation: over a bottom-nav shell, raise the token with one line — see the recipe below. It should never cover tab bars.
  • Animation: rises 8px and fades in, fades out on leave — CSS only, prefers-reduced-motion disables it.
  • No-JS fallback (honest): the element is hidden (opacity: 0; pointer-events: none); with JS off the page renders and works, the snackbar just never shows. Toggle is-visible from your own code for a zero-flint path.

Recipe — snackbar above a persistent bottom nav:

.fl-snackbar {
  --fl-snackbar-inset: calc(var(--fl-tabbar-h) + var(--fl-space-2) + env(safe-area-inset-bottom, 0px));
}

Accessibility

  • Give the snackbar role="status" — screen readers announce it politely when it appears, without moving focus.
  • Because it is announced and then vanishes, don't put anything the user must read in a snackbar — anything important belongs in the page itself.
  • The action is a real <button> — focusable and activatable like any control; it doesn't need type="button" outside a form, but it doesn't hurt. It sits at the trailing edge of the sheet (M2); the message takes the remaining width.
  • Contrast: --fl-surface white on --fl-text #1f1f1f is ~16:1; the bright action (--fl-accent-inverse #8ab4f8) is ~7.9:1 on the same surface — both clear AA.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

Plain message — shown by any trigger, auto-dismissed after 4s:

<button class="fl-btn" data-fl-open="snack-saved">Save conversation</button>

<div class="fl-snackbar" id="snack-saved" role="status">
  Conversation saved to your Favorites
</div>

Message + Undo — the single action, bright accent on the inverse surface; the click handler is author code:

<div class="fl-snackbar" id="snack-archived" role="status">
  Your photo has been archived
  <button class="fl-snackbar__action" type="button">Undo</button>
</div>

<script>
  document.querySelector("#snack-archived .fl-snackbar__action")
    .addEventListener("click", function () {
      // …amend the process, then confirm with its own snackbar
      flint.snackbar.show(document.getElementById("snack-restored"));
    });
</script>

Programmatic control — same clock, same one-at-a-time rule:

flint.snackbar.show(document.getElementById("snack-sent"));
flint.snackbar.hide(document.getElementById("snack-sent"));

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-textThe inverse container fill
--fl-surfaceThe label color on the container
--fl-accent-inverseThe action text (readable on dark)
--fl-radiusCorner radius (4px)
--fl-snackbar-insetGutter to the bottom and (on phones) side edges, safe-area included; default 8px + inset
--fl-z-snackbarLayer order (above FABs, below modal surfaces)
--fl-dur / --fl-easeShow/hide animation timing
 
:root {
  --fl-accent-inverse: #c9a6ff;   /* a purple action, still AA on --fl-text */
  --fl-radius: 0;                 /* square snackbars */
}
