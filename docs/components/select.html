Select

The styled native <select> — field-family box with a drawn chevron; the popup stays platform-styled, by design.

Usage

The select is the native <select> wearing the field-family clothes: same 44px box, same label/helper/error markup, with a chevron drawn in CSS instead of the platform arrow. It exists because a visible radio group stops scaling past a handful of options — the select is the honest fallback, not a styled imitation.

Do use it when

  • One choice from more than ~5 options — regions, countries, sort orders, plan tiers.
  • The option list is long or data-driven; a native select scrolls and type-aheads for free.
  • It sits in a form next to text fields — the shared fl-field markup keeps the rhythm identical.

Don't use it when

  • 2–5 options — that is a radio group; visible options beat a hidden dropdown.
  • You need a custom menu (icons, search, multi-line options) — that is the listbox pattern, planned for 0.4/0.5 with the overlay infrastructure. Don't hand-roll it; that's how libraries grow 300 lines of fragile focus-management JS.
  • Multiple selection — multiple selects are not styled; use a checkbox group.

The popup is browser-controlled — on purpose

appearance:none only reshapes the closed control. The open dropdown (its panel, rows and highlight) is drawn by the browser/OS. That keeps type-ahead, scroll, long lists and mobile pickers correct with zero JS. Flint will not restyle the popup until the custom listbox lands with proper focus management.

Selection controls

Anatomy

  1. The field box — exactly fl-field__input: 44px, 1px border, 4px radius, the same hover/focus/error/disabled states as text fields.
  2. Chevron — drawn via a background-image at the right edge, replacing the platform arrow that appearance:none removes.
  3. Helper text — same fl-field__help slot; error and filled variants compose like any field.

Behavior

  • Same markup as fields: wrap the select in <label class="fl-field"> with fl-field__label and optional fl-field__help. The class fl-field__input is the only select-specific class needed — select.fl-field__input switches on the chevron automatically.
  • All field states compose: fl-field--filled (tint fill + bottom indicator), fl-field--error / aria-invalid="true" (red border + red helper), and the native disabled attribute (dimmed box, chevron kept).
  • The popup is native: opening it draws a browser/OS-styled list. Closed-control styling is what the CSS guarantees; open-menu styling is platform behavior and differs between browsers — this is documented, not hidden.
  • Selected value renders as text — style it with the default body size/weight; don't restyle per-state, the platform repaints it on change.
  • Option styling is not supported — <option> elements are mostly unstyleable by design; keep their content plain text.

Accessibility

  • The wrapping label names the control natively; no aria-label needed when fl-field__label is present.
  • The native select is one of the best-supported controls for assistive tech — announced name, role, value, and expanded state come from the platform.
  • Keep the first option meaningful on optional fields ("Select a country" reads fine; "—" does not) and mark genuinely required selects with required so the platform validates.
  • Validation errors: set aria-invalid="true" (which the CSS keys off) and put the reason in fl-field__help.

Code

Two files bring the library in; the select needs no class of its own — it reuses the field markup.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<!-- Outlined (default) -->
<label class="fl-field">
  <span class="fl-field__label">Workspace type</span>
  <select class="fl-field__input">
    <option>Starter</option>
    <option selected>Team</option>
    <option>Business</option>
  </select>
</label>

<!-- With helper text -->
<label class="fl-field">
  <span class="fl-field__label">Region</span>
  <select class="fl-field__input">
    <option selected>Europe (Frankfurt)</option>
    <option>North America (Iowa)</option>
  </select>
  <span class="fl-field__help">Choose the region closest to your users</span>
</label>

<!-- Error / filled / disabled compose like any field -->
<label class="fl-field fl-field--error">
  <span class="fl-field__label">Billing country</span>
  <select class="fl-field__input" aria-invalid="true">
    <option selected>Select a country</option>
  </select>
</label>

<label class="fl-field fl-field--filled">
  <span class="fl-field__label">Sort by</span>
  <select class="fl-field__input">
    <option selected>Most recent</option>
  </select>
</label>

<label class="fl-field">
  <span class="fl-field__label">Plan</span>
  <select class="fl-field__input" disabled>
    <option>Free — managed by your administrator</option>
  </select>
</label>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-borderClosed-control border; filled fill is --fl-divider
--fl-accentFocus border/ring and the filled indicator
--fl-errorError border, ring and helper text
--fl-disabledDisabled text color
--fl-radiusCorner radius (4px)

Note: the chevron glyph is a fixed-color image (it does not follow a token). If you retheme --fl-icon, swap the chevron by overriding .fl-field select.fl-field__input's background-image with your own SVG.

:root {
  --fl-divider: #f1f3f4;   /* filled select fill follows */
}
/* custom chevron */
.fl-field select.fl-field__input {
  background-image: url("data:image/svg+xml,...your chevron...");
}
