Select

The Material exposed dropdown — the menu anchored to a field. The current value sits above the same 48px option list, and a hidden input carries it into the form.

Usage

The select is Material's exposed dropdown menu — the variation filed under Menus, not under text fields. It is not an imitation of a dropdown: it is the same fl-menu, the same 48px fl-option rows and the same state language, anchored to a field box instead of an icon button. The field shows the current value; a hidden input carries it into the form.

Do use it when

  • One choice from more than ~5 options — regions, countries, sort orders, plan tiers.
  • It sits in a form next to text fields — the shared fl-field markup keeps the rhythm identical, and the open list reads like every other menu in the product.
  • The chosen value must be visible above the list while choosing — that is the spec's defining behaviour.

Don't use it when

  • 2–5 options — that is a radio group; visible options beat a hidden list.
  • You need search, free text or rich rows — an editable dropdown is a separate M2 variation. Compose a menu with a search field, or use a dialog.
  • Multiple selection — use a checkbox group, or the native select with multiple.
  • The page must work without JavaScript — the native select is the platform control for exactly that case.

One component, two anchors

A menu is this panel anchored to a button; a select is the same panel anchored to a field. Row meaning differs (action vs value), the panel does not — that is why they complement each other.

Menu

Anatomy

  1. The field box — owns every pixel of chrome: 44px, 1px border, 4px radius, and the hover/focus/error/disabled states shared with text fields. The open list is the field's activated state.
  2. The anchor and the value — a real <button role="combobox"> filling the box, showing the current row's label. The label's for points at it, so clicking the label opens the list.
  3. The panel — the same fl-menu as every action menu: 1px border, 4px radius, 8px padding, 48px rows, no shadow. fl-menu--fullwidth attaches it to the field and gives it the field's width.
  4. The current row — a persistent --fl-divider tint, not the menuitemradio check glyph (that is the multi-choice idiom).

The chevron is a 20px mask filled with --fl-icon, 12px from the border, and flips in the activated state. It is not drawn into the markup, so it follows the token and swaps with --fl-select-chevron. The hidden input is not in the diagram: it submits the value.

Behavior

  • One structure: a fl-field root, a fl-field__box holding the anchor and a hidden input, and an fl-menu with role="listbox". The panel is a sibling of the box; the browser's top layer means nothing clips it.
  • Opening: click anywhere in the box, click the label, press Enter or Space, or ArrowDown/ArrowUp. The list attaches directly under the field at the field's width, flips above when there is no room below, and caps to the roomier side with its own scrollbar when the options are long.
  • Activated: the accent border (filled: the 2px bottom indicator), the flipped chevron and the tinted current row. The state is read from :popover-open, so it is the platform's truth, not a second JS flag.
  • Choosing: click a row or press Enter/Space on it. aria-selected moves, the anchor text updates, the hidden input takes the row's value (or its text), the list closes, focus returns to the field, and an input then a change event bubble from the hidden input. Re-choosing the current row only closes.
  • Keyboard: ↑/↓ move, Home/End jump, letters type-ahead, Escape closes without choosing and returns focus, Tab closes and returns focus to the field (a second Tab leaves it). Disabled rows are skipped by the arrow cycle and the type-ahead.
  • Field states compose: fl-field--filled (tint fill + bottom indicator), fl-field--error / aria-invalid="true" (red border, label and helper), and disabled on the anchor (dimmed, cannot open). Disable the hidden input too if a disabled field must not submit.
  • Form reset restores the hidden input's default value and flint.js brings the painted value back with it.

Choosing needs flint.js

The panel opens without JavaScript (popovertarget is HTML), but rows cannot choose and the panel is not anchored, because both need script. For no-JS pages use the native select below — the same field box with the platform's list.

Accessibility

  • The anchor is a real <button> carrying the select-only combobox pattern: role="combobox", aria-haspopup="listbox", aria-controls pointing at the panel, and aria-expanded (synced by flint.js). Keeping the button element means label clicks, Enter/Space and the platform's activation all still work.
  • Name the anchor with the label only: aria-labelledby="label-id" announces "Workspace type" and the browser exposes the visible text as the combobox's value ("Team"), so the value is not repeated in the name. A <label for> pointing at a button is valid and makes the label open the list; keep both, or omit for if you only want the aria-labelledby name.
  • The panel is role="listbox" named by the label; rows are <button role="option"> with aria-selected. Focus moves into the list, so assistive tech reads the real option under the keyboard — no aria-activedescendant bookkeeping.
  • Escape closes and returns focus; choosing returns focus to the field. The list is not a tab stop: Tab closes it.
  • Required is yours to enforce. A hidden input is barred from constraint validation, so required on it does nothing. Put aria-required="true" on the combobox anchor — valid on role="combobox", unlike on a plain button — and run the check in the code recipe; the error state is the field's own aria-invalid styling.

Known gaps

  • JavaScript is required to choose. The closed field renders identically without it; the list opens but cannot select. The native select is the no-JS path.
  • No native constraint validation. required is author-checked (see above). Frameworks can own this in their wrapper.
  • Popover API floor: Chrome/Edge 114, Safari 17, Firefox 125 — the same floor as the menu. Older browsers keep the list closed; the closed field is unchanged.
  • No grouped options. optgroup has no listbox equivalent here yet; use the native select when groups are load-bearing.
  • Not an editable dropdown. Free-text entry ("type a value not in the list") is a separate M2 variation and not shipped.
  • Static label. The label sits above the box, like every Flint field; M2's exposed dropdown floats the label into the border. This is the library's recorded field deviation.
  • Mobile shows the in-page list, not the OS picker. M2 permits the native picker on touch; Flint keeps one structure at every width.

Code

Two files bring the library in. The select's behaviour lives in flint.js; without it the field renders but cannot choose.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

The initial state is the markup: one row is aria-selected, the anchor shows its label, and the hidden input holds its value. Keep those three in agreement (a framework renders all three from one prop).

<!-- Outlined (default) -->
<div class="fl-field fl-select">
  <label class="fl-field__label" id="type-label" for="type-anchor">Workspace type</label>
  <div class="fl-field__box">
    <input type="hidden" name="type" value="team">
    <button class="fl-select__anchor" type="button" role="combobox" id="type-anchor"
            popovertarget="type-menu" aria-controls="type-menu"
            aria-haspopup="listbox" aria-expanded="false"
            aria-labelledby="type-label">
      <span class="fl-select__value" id="type-value">Team</span>
    </button>
  </div>
  <div class="fl-menu fl-menu--fullwidth" id="type-menu" popover role="listbox"
       aria-labelledby="type-label">
    <button class="fl-option" role="option" type="button" value="starter" aria-selected="false">Starter</button>
    <button class="fl-option" role="option" type="button" value="team" aria-selected="true">Team</button>
    <button class="fl-option" role="option" type="button" value="business" aria-selected="false">Business</button>
  </div>
  <div class="fl-field__footer">
    <span class="fl-field__help">Choose the plan for this workspace</span>
  </div>
</div>

<!-- Filled, error and disabled use the field classes, unchanged -->
<div class="fl-field fl-select fl-field--filled"> … </div>
<div class="fl-field fl-select fl-field--error"> … </div>
<div class="fl-field fl-select">
  <div class="fl-field__box">
    <input type="hidden" name="plan" value="free" disabled>
    <button class="fl-select__anchor" type="button" role="combobox" disabled
            popovertarget="plan-menu" aria-haspopup="listbox" aria-expanded="false">
      …
    </button>
  </div>
</div>

Listen for the value the way you would with a native select — the events bubble from the hidden input, so a form-level listener catches every select:

document.querySelector("form").addEventListener("change", function (e) {
  if (!e.target.name) return;
  console.log(e.target.name, e.target.value);   // e.g. "type team"
});

Required selects

required on the hidden input is ignored by the platform. Mark the anchor aria-required="true" and check on submit; the field's existing error styling does the rest:

<form>
  <div class="fl-field fl-select">
    …
    <button class="fl-select__anchor" type="button" role="combobox" aria-required="true" …>…</button>
  </div>
</form>
var form = document.querySelector("form");

form.addEventListener("submit", function (e) {
  var anchor = form.querySelector(".fl-select__anchor[aria-required='true']");
  if (!anchor) return;
  var input = anchor.closest(".fl-select").querySelector('input[type="hidden"]');
  if (input.value) return;
  e.preventDefault();
  anchor.setAttribute("aria-invalid", "true");
  anchor.focus();
});

/* Clear the error once a value is chosen (change bubbles from the input). */
form.addEventListener("change", function (e) {
  var field = e.target.closest(".fl-select");
  if (field) field.querySelector(".fl-select__anchor").removeAttribute("aria-invalid");
});

Native select

M2's placement note allows the filled and outlined variations to open a native picker instead. That control is still here, and it is the honest choice when JavaScript is unavailable, when multiple is needed, or when grouped optgroups matter. It wears the same box and chevron; the popup is the platform's.

<div class="fl-field">
  <label class="fl-field__label" for="native-type">Workspace type</label>
  <div class="fl-field__box">
    <select class="fl-field__input" id="native-type">
      <option>Starter</option>
      <option selected>Team</option>
      <option>Business</option>
    </select>
  </div>
</div>

The same closed-control styling, native value submission and native validation. Its open list is drawn by the browser/OS and cannot be themed — that is the trade, and the reason the exposed dropdown is the default. The data table's compact page-size control stays native because it is a footer control, not a field.

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild. The select reuses the field and menu tokens; only the chevron is new:

TokenAffects
--fl-borderField border; the open panel's border (filled fill is --fl-divider)
--fl-accentFocus/activated border and ring, the filled indicator
--fl-errorError border, ring, label and helper
--fl-disabledDisabled value text and disabled rows
--fl-dividerFilled fill and the current row's tint
--fl-hoverRow hover
--fl-iconChevron fill
--fl-select-chevronThe chevron glyph (a url() mask)
--fl-radiusField and panel corners
--fl-option-hOption row height (48px)
--fl-surfacePanel background
 
:root {
  --fl-select-chevron: url("data:image/svg+xml,...your chevron...");
  --fl-divider: #f1f3f4;   /* current row + filled fill follow */
}
