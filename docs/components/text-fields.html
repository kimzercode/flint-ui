Text fields

Outlined and filled text fields in the Gmail-2020 style — 44px inputs, flat error states, helper text, zero JavaScript.

Usage

Text fields collect free-form input. The default is the outlined style (1px border, no fill); fl-field--filled switches to the M2 filled style (tinted fill, flat bottom indicator) for dense forms and search boxes. Both are plain HTML inputs — the CSS only styles them, so autofill, validation and mobile keyboards all behave natively.

Do use it when

  • You need single-line input (email, name, search) — wrap the input in <label class="fl-field"> with a fl-field__label span.
  • You need multi-line input — a real <textarea class="fl-field__input">; it auto-heights and resizes vertically only.
  • The form needs inline guidance or validation — fl-field__help renders under the input and doubles as the error slot.

Don't use it when

  • One value out of a known list — that is a select or checkboxes/radios; a text field invites typos you then have to validate away.
  • You need a custom dropdown menu — the custom listbox is planned for 0.4 with the overlay infrastructure; until then the native control is the honest choice.
  • The value is display-only — plain text, not a disabled field; disabled fields are for genuinely unavailable input.

Anatomy

  1. Label — 12px/500 above the input; it is a real <label> wrapping the control, so clicking it focuses the field.
  2. Input — 44px tall, 1px --fl-border, 4px radius; hover darkens the border, focus takes the accent border plus a flat 2px-looking inset ring.
  3. Helper text — 12px under the input; on error it recolors to --fl-error and the border follows.
  4. Filled variant — tinted --fl-divider fill, flat accent bottom indicator (2px on focus via inset box-shadow).

Behavior

  • Structure is the API: fl-field is a <label> wrapping fl-field__label, the input, and optional fl-field__help — in that order. The association is native, no for/id wiring needed.
  • Two ways to mark an error: add fl-field--error on the label, or set aria-invalid="true" on the input — either alone works and they stack. The second exists so JS validation code never has to know the class name.
  • Helper doubles as the error slot — reuse the same element and swap its text; the color follows the error state automatically.
  • Filled variant (fl-field--filled) keeps the same label/help markup; only the box changes. Error state recolors its bottom indicator instead of the full border.
  • Textarea is <textarea class="fl-field__input"> — height auto, rows sets the initial size, resize is vertical-only so the layout can't blow out.
  • Disabled is the native attribute — dimmed text on a flat fill, hover darkening switched off. Dim the helper text by writing it in secondary color (the default) — the CSS does not style the label, so prefer removing optional guidance on disabled fields.
  • Custom dropdown is not here yet — a styled native select ships in this release; the custom listbox menu is planned for 0.4 with the overlay work.

Accessibility

  • The label wraps the input — real <label> association for free, including click-to-focus and screen-reader naming.
  • Mark errors with aria-invalid="true" (which the CSS keys off) and keep the visible error text in fl-field__help — never color alone; the text is the announcement.
  • Never remove the focus style — it is the only focus indicator the flat input has (accent border + inset ring).
  • placeholder is a hint, not a label — always ship a fl-field__label; placeholders disappear on input and are skipped by some screen readers.
  • Disabled inputs are skipped by tab order — that is correct; if the field must stay discoverable, prefer readonly + explanation over disabled.

Code

Two files bring the library in; the markup below covers every state.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<!-- Outlined field (default) -->
<label class="fl-field">
  <span class="fl-field__label">Email</span>
  <input class="fl-field__input" type="email" placeholder="you@example.com">
</label>

<!-- With helper text -->
<label class="fl-field">
  <span class="fl-field__label">Password</span>
  <input class="fl-field__input" type="password">
  <span class="fl-field__help">At least 8 characters</span>
</label>

<!-- Error: class on the label OR aria-invalid on the input -->
<label class="fl-field fl-field--error">
  <span class="fl-field__label">Email</span>
  <input class="fl-field__input" type="email" value="not-an-email" aria-invalid="true">
  <span class="fl-field__help">Enter a valid email address</span>
</label>

<!-- Filled variant -->
<label class="fl-field fl-field--filled">
  <span class="fl-field__label">Search</span>
  <input class="fl-field__input" type="text">
</label>

<!-- Textarea -->
<label class="fl-field">
  <span class="fl-field__label">Notes</span>
  <textarea class="fl-field__input" rows="3"></textarea>
</label>

<!-- Disabled -->
<label class="fl-field">
  <span class="fl-field__label">Workspace URL</span>
  <input class="fl-field__input" type="text" value="acme.flint.app" disabled>
</label>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-errorError border, ring and helper text
--fl-borderOutlined border; filled fill is --fl-divider
--fl-accentFocus border/ring and the filled indicator
--fl-disabledDisabled text color
--fl-radiusInput corner radius (4px)
--fl-fs-captionLabel and helper size (12px)
 
:root {
  --fl-error: #b3261e;      /* deeper error red */
}
