Text fields

Outlined and filled text fields in the Gmail-2020 style — affixes and icons inside the border, helper and counter on the footer line, a working password toggle. Zero JavaScript except the toggle.

Usage

Text fields collect free-form input. The default is the outlined style (1px border, no fill); fl-field--filled switches to the M2 filled style (tinted fill, flat bottom indicator) for dense forms. Both are plain HTML controls — the CSS only styles them, so autofill, validation and mobile keyboards all behave natively.

Do use it when

  • You need single-line input (email, name, price, search) — a control inside a fl-field__box with a fl-field__label above.
  • You need multi-line input — a real <textarea class="fl-field__input">; it resizes vertically, or grows with content with the opt-in fl-field__input--grow.
  • The form needs inline guidance or validation — fl-field__help on the footer line doubles as the error slot.
  • The value needs units or context in the box — a prefix ($), a suffix (lbs, a domain), a leading search icon.

Don't use it when

  • One value out of a known list — that is a select or checkboxes/radios; a text field invites typos you then have to validate away.
  • You need a custom dropdown menu — the native control is the honest choice until the listbox work lands.
  • The value is display-only — plain text, not a disabled field; disabled fields are for genuinely unavailable input.

Deliberately not floating labels

Material 2 floats the label into the border notch. Flint keeps the label static above the field — the classic idiom, and M2's own "text fields with independent labels" pattern. It is the better accessibility shape (the label never doubles as a placeholder) and it is a permanent decision, not a missing feature. The 44px field height and 12px label follow from it.

Select — same static-label family

Anatomy

  1. Label — 12px/500 above the field; a real <label for>, so clicking it focuses the control. It never wraps the box (a label may not contain buttons, and helper text inside a label leaks into the accessible name).
  2. Box — 44px tall, 1px --fl-border, 4px radius. The box owns every pixel of chrome: hover darkens the border, focus takes the accent border plus a real 2px outline, error recolors both. The control inside is borderless.
  3. Affixes — fl-field__prefix / fl-field__suffix: 16px inside the border, in the value color (--fl-text), any width. Dimmed when the field is disabled.
  4. Footer line — help left, character counter right (fl-field__counter, tabular numerals). The counter stays put when the help text swaps to an error message.
  5. Filled variant — tinted --fl-divider fill, top corners only, flat bottom indicator (2px on focus via inset box-shadow — no full ring).

Behavior

  • Structure is the API: fl-field is a <div> holding fl-field__label (a <label for>), a fl-field__box containing the control (and any affixes/icons), and an optional fl-field__footer. The box draws the border; the control is borderless inside it. That one structure covers plain fields, affixes, icons, selects and textareas.
  • Two ways to mark an error: add fl-field--error on the field, or set aria-invalid="true" on the control — either alone works and they stack. Either path recolors the border (or the filled indicator), the label and the help text. The attribute exists so JS validation code never has to know the class name.
  • Helper doubles as the error slot — reuse the same element and swap its text; the color follows the error state automatically. Link it with aria-describedby so screen readers announce it.
  • Affixes live inside the border at 16px from the edge, in the value color. They are plain siblings of the control, so any width works and a long value scrolls without running under them. Prefix or leading icon, suffix or trailing icon — don't combine both on one edge (M2 agrees).
  • Icons — fl-field__icon with --leading or --trailing. A decorative icon is a <span aria-hidden="true">; an interactive one is a <button type="button"> (44px-wide target, hover fill, visible focus ring).
  • Password toggle — put data-fl-password-toggle on a trailing icon button pointing at the input with aria-controls. flint.js flips password↔text, restores the caret, swaps aria-label ("Show password"/"Hide password") and toggles an is-revealed class you can use to swap the eye icon. It is the only JavaScript in this component — without flint.js the field is a normal password input and the button does nothing.
  • Counter is author code: listen for input and write value.length + "/" + maxlength into fl-field__counter. Keep it aria-hidden — maxlength is what assistive tech needs.
  • Filled variant (fl-field--filled) keeps the same markup; only the box changes: tinted fill, top corners only, bottom indicator instead of a full border (2px on focus).
  • Textarea is <textarea class="fl-field__input"> — height auto, rows sets the initial size, resize is vertical-only. Add fl-field__input--grow to make it grow with content (field-sizing: content, capped at 240px; browsers without field-sizing keep the rows height).
  • Disabled is the native attribute — flat fill, dimmed value, affixes and icons; hover darkening switched off. Prefer removing optional guidance rather than dimming it.
  • A field without a visible label needs aria-label on the control (a search box with only a leading icon, for example).

Accessibility

  • The label is a real <label for> — clicking it focuses the control and screen readers read it as the name. It is deliberately not a wrapper: a label containing a button is invalid HTML, and helper text inside a label can leak into the control's accessible name.
  • Link the help text with aria-describedby; it is the announcement for both guidance and error text.
  • Never color alone — errors are also aria-invalid plus visible error text; the color change is the third signal, not the only one.
  • Counter is aria-hidden — announcing every keystroke is noise; the native maxlength is what assistive tech uses. If you want remaining characters announced, add your own aria-live region with sensible throttling.
  • Icon buttons must have names — aria-label on the toggle ("Show password"), and a meaningful name on any other interactive icon. Decorative icons get aria-hidden="true".
  • The toggle's name describes the action and changes with the state ("Show password" ↔ "Hide password"). There is no aria-pressed — a changing name plus a pressed state announces contradictory information.
  • Never remove the focus style — the accent border plus the 2px outline is the only focus indicator the field has; it is a real outline, so it survives forced-colors mode where box-shadows do not.
  • placeholder is a hint, not a label — always ship a fl-field__label (or aria-label); placeholders disappear on input and are skipped by some screen readers.
  • Disabled inputs are skipped by tab order — that is correct; if the field must stay discoverable, prefer readonly + explanation over disabled.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

flint.js is only needed for the password toggle; every other field feature is CSS.

A plain field:

<div class="fl-field">
  <label class="fl-field__label" for="email">Email</label>
  <div class="fl-field__box">
    <input class="fl-field__input" id="email" type="email" autocomplete="email">
  </div>
  <div class="fl-field__footer">
    <span class="fl-field__help">We never share it</span>
  </div>
</div>

Affixes — units live inside the border, in the value color:

<div class="fl-field">
  <label class="fl-field__label" for="price">Price</label>
  <div class="fl-field__box">
    <span class="fl-field__prefix" aria-hidden="true">$</span>
    <input class="fl-field__input" id="price" type="text" inputmode="decimal">
    <span class="fl-field__suffix">USD</span>
  </div>
</div>

Icons — decorative as a span, interactive as a button. The password toggle is the one piece of library JS:

<!-- decorative leading icon -->
<div class="fl-field__box">
  <span class="fl-field__icon fl-field__icon--leading" aria-hidden="true">
    <svg …></svg>
  </span>
  <input class="fl-field__input" type="search" aria-label="Search">
</div>

<!-- password toggle (flint.js) -->
<div class="fl-field">
  <label class="fl-field__label" for="pw">Password</label>
  <div class="fl-field__box">
    <input class="fl-field__input" id="pw" type="password" autocomplete="current-password">
    <button type="button" class="fl-field__icon fl-field__icon--trailing"
            data-fl-password-toggle aria-controls="pw" aria-label="Show password">
      <svg …></svg>
    </button>
  </div>
</div>

Footer line — help left, counter right. The counter is author JS:

<div class="fl-field">
  <label class="fl-field__label" for="bio">Bio</label>
  <div class="fl-field__box">
    <textarea class="fl-field__input" id="bio" rows="3" maxlength="100" aria-describedby="bio-help"></textarea>
  </div>
  <div class="fl-field__footer">
    <span class="fl-field__help" id="bio-help">Markdown is fine</span>
    <span class="fl-field__counter" id="bio-count" aria-hidden="true">0/100</span>
  </div>
</div>
<script>
  var bio = document.getElementById("bio"),
      count = document.getElementById("bio-count");
  bio.addEventListener("input", function () {
    count.textContent = bio.value.length + "/100";
  });
</script>

Variants and modifiers:

<div class="fl-field fl-field--filled">…</div>          <!-- tinted fill, bottom indicator -->
<div class="fl-field fl-field--error">…</div>           <!-- or aria-invalid on the control -->
<textarea class="fl-field__input fl-field__input--grow" …></textarea>  <!-- grows with content -->

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-field-hField height (44px; also the icon target width)
--fl-borderResting border
--fl-text / --fl-text-secondaryValue + affix color / label + help + counter
--fl-dividerFilled variant fill
--fl-hoverDisabled fill, icon hover
--fl-accentFocus border + outline, filled focus indicator
--fl-errorError border/indicator, error text
--fl-disabledDisabled value, affixes, icons
--fl-radiusCorner radius (4px)
--fl-dur / --fl-easeState transitions
 
:root {
  --fl-field-h: 48px;   /* roomier fields — icons follow automatically */
}
