Bottom sheet

A sheet docked to the bottom edge — modal on the native <dialog>, standard as a persistent plain element. Same interior contract, two platform roots.

Usage

A bottom sheet presents choices or a compact task in the context the user is already in. Material 2 defines three types; Flint ships two — the two that earn their keep on the web.

Modal sheet

Blocks the screen behind a scrim and dismisses as soon as the choice is made. Use it for:

  • Choosing from a set — sort order, account picker, "add to" destinations. The canonical sheet is a vertical option list.
  • Compact forms — "new label", quick compose, a filter with two or three controls.
  • Details that shouldn't navigate — long metadata or an "about" panel that belongs to the current screen.

Standard sheet

Persistent and non-modal: no scrim, the page stays interactive and scrolls behind it. Use it for a state the app keeps — a mini-player, a cart summary, a "3 items selected" bar. It is plain CSS (a fixed block element); there is nothing to open and nothing to dismiss.

Don't use a sheet for

  • Destructive or blocking decisions — "delete everything?" is dialog territory; a sheet implies "this is still the same task".
  • Full-screen forms — real compose and settings sub-pages are the dialog's --fullscreen type.
  • Feedback — "Message sent" is a snackbar, never a sheet.
  • An "expanded" state of a collapsed pill — that is M2's expanding sheet, which Flint deliberately does not implement: on the web its collapsed state is a FAB or a sticky action bar and its expanded state is the dialog's --fullscreen. The only thing left would be the morph between them — a gesture state machine this library doesn't need.

No drag gesture

M2 sheets have no drag handle, and Flint doesn't fake one — there is no swipe-to-dismiss either: a vertical drag fights the sheet's own scroll. Sheets close on scrim tap, Escape, their own rows or a close action.

Dialog component

Anatomy

  1. Title — short, 16px/500; optional for pure option lists where the rows are self-describing.
  2. Content slot — exactly one of __list, __body or __grid; it scrolls while title and actions stay pinned. The surface has no padding — each slot owns its inset.
  3. Actions — right-aligned, same button idiom as the dialog; often unnecessary for pure pick-one lists. They carry the safe-area inset.
  4. Scrim — modal only, 32% black, shared with the dialog and drawer. A standard sheet has none.

Behavior

  • Two roots, one contract: the modal sheet is a <dialog> (only dialogs can be modal); the standard sheet is any block element with fl-sheet--standard. The interior — surface, title, one content slot, actions — is identical, so the CSS is written once.
  • Modal lifecycle: data-fl-open="sheet-id" opens it, data-fl-close inside closes it, and <form method="dialog"> records the pressed row or button in dialog.returnValue — picking "Unread first" returns "unread" with zero JavaScript.
  • Height: the initial height is capped at 50dvh — M2's "initial position at 50% of the screen". Shorter content sizes the sheet; taller content scrolls inside it. Content that needs the whole screen gets fl-sheet--full (100dvh, internal scroll) — and a close action is required in that state, because the scrim can't be the only way out of a full-screen surface.
  • Dismissal (modal): Escape, scrim tap, the rows and the actions all close it; focus returns to the invoker on every path. There is no swipe-to-dismiss — a vertical drag has to arbitrate against the sheet's own scroll, and a gesture that sometimes scrolls and sometimes closes is worse than none.
  • Scroll: the content slot scrolls inside the surface (overscroll-behavior: contain keeps the page behind from rubber-banding); the page itself is scroll-locked while a modal sheet is open — one CSS rule shared across dialog, sheet and drawer.
  • Stacking: a dialog can open over the sheet — the top layer stacks in DOM order and Escape peels only the top one.
  • Animation: slides up on open, fades out on close — CSS only, prefers-reduced-motion disables it.
  • No-JS fallback (honest): the standard sheet is plain CSS and works without JavaScript. The modal sheet stays hidden — call showModal() yourself with one line, or drive it from your own code. See demos/dialog.html for the raw lifecycle.

Placement

  • Mobile (<600px): full-bleed to the bottom edge, 8px top radius. On the web the browser owns the edges, so the sheet docks to the layout viewport, not behind the URL bar.
  • Desktop (≥600px): a 560px card docked to the bottom edge, with a taller cap (min(86dvh, 640px)). Never full-width on large screens — an edge-to-edge tray at desktop width is a layout, not a sheet.
  • Safe areas: the actions row and the standard sheet add env(safe-area-inset-bottom), so the home indicator never covers a button.
  • Don't inset a sheet on all sides — that's a card or (small and inverse) a snackbar, not a sheet.
  • Standard sheet layering: it sits below the snackbar (--fl-z-sheet: 18 vs --fl-z-snackbar: 25) so status messages always win the bottom edge. The page needs padding-bottom clearance at least as tall as the sheet.

Contents

One content slot per sheet — no nesting, no negative margins:

  • __list — option rows, full-bleed. Rows are fl-option at 56px here (the surface sets --fl-option-h; dialogs keep 48px — both are spec numbers, one row component).
  • __grid — the "Open in…" idiom: a fixed 3-column grid of icon+label tiles. The tiles are the same fl-option re-oriented vertically.
  • __body — fields and prose; owns the side insets and scrolls.

Accessibility

  • Give the sheet aria-labelledby pointing at its title (skip this only when there is deliberately no title and the rows are self-describing).
  • Option rows are real <button>s or <label>+input pairs — native focus, native activation, no tabindex games. 56px rows exceed the 48px touch-target minimum.
  • The inert background is native: nothing behind a modal sheet is focusable or announced while it's open. The standard sheet is not inert — keep its controls few and its content a state, not a task.
  • Full-bleed rows draw the focus ring inside the row (the global ring would land outside the surface and get clipped) — don't remove it; it's what makes keyboard position visible.
  • Known gap: no swipe-to-dismiss (see Behavior) and no Android back-gesture integration — on Android the system back navigates away instead of closing the sheet. All four web dismissal paths work; a history-based fix is planned for 0.5.

Menu sheet — the canonical M2 option list. Rows are 56px fl-option; one method="dialog" form per row, picking one closes and records its value:

<button class="fl-btn" data-fl-open="sheet-sort">Sort conversations</button>

<dialog class="fl-sheet" id="sheet-sort" aria-labelledby="sheet-sort-t">
  <div class="fl-sheet__surface">
    <h2 class="fl-sheet__title" id="sheet-sort-t">Sort conversations</h2>
    <div class="fl-sheet__list">
      <form method="dialog">
        <button class="fl-option" value="date" autofocus>Date received</button>
      </form>
      <form method="dialog">
        <button class="fl-option" value="unread">Unread first</button>
      </form>
    </div>
    <div class="fl-sheet__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
    </div>
  </div>
</dialog>

Grid sheet ("Open in…") — the grid slot is the form, so every tile submits and closes with its value:

<dialog class="fl-sheet" id="sheet-open" aria-labelledby="sheet-open-t">
  <div class="fl-sheet__surface">
    <h2 class="fl-sheet__title" id="sheet-open-t">Open in…</h2>
    <form class="fl-sheet__grid" method="dialog">
      <button class="fl-option" value="drive" autofocus>
        <svg …>…</svg> Drive
      </button>
      <button class="fl-option" value="mail">
        <svg …>…</svg> Mail
      </button>
      <button class="fl-option" value="photos">
        <svg …>…</svg> Photos
      </button>
    </form>
  </div>
</dialog>

Form sheet — fields in the scrollable body, actions pinned:

<dialog class="fl-sheet" id="sheet-label" aria-labelledby="sheet-label-t">
  <div class="fl-sheet__surface">
    <h2 class="fl-sheet__title" id="sheet-label-t">New label</h2>
    <form class="fl-sheet__body" method="dialog" id="label-form">
      <div class="fl-field">
        <label class="fl-field__label" for="sheet-label-name">Label name</label>
        <div class="fl-field__box">
          <input class="fl-field__input" id="sheet-label-name" placeholder="e.g. Finance" autofocus>
        </div>
      </div>
    </form>
    <div class="fl-sheet__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
      <button class="fl-btn fl-btn--filled" form="label-form" value="create">Create</button>
    </div>
  </div>
</dialog>

Full-screen sheet — for content that needs the whole screen. A close action is required in this state:

<dialog class="fl-sheet fl-sheet--full" id="sheet-about" aria-labelledby="sheet-about-t">
  <div class="fl-sheet__surface">
    <h2 class="fl-sheet__title" id="sheet-about-t">About</h2>
    <div class="fl-sheet__body">
      <p>Long content scrolls inside the body while the title and the
         close action stay pinned.</p>
    </div>
    <div class="fl-sheet__actions">
      <form method="dialog"><button class="fl-btn fl-btn--filled" value="ok" autofocus>Close</button></form>
    </div>
  </div>
</dialog>

Standard sheet — persistent, non-modal, zero JS. Not a <dialog>: any block element carries the class. The page's scroll container needs padding-bottom clearance at least as tall as the sheet:

<aside class="fl-sheet fl-sheet--standard" aria-label="Now playing">
  <div class="fl-sheet__surface">
    <div class="fl-sheet__body">
      <div style="display:flex; align-items:center; gap:16px">
        <!-- track info + play/next icon buttons -->
      </div>
    </div>
  </div>
</aside>

<!-- the page clears the sheet -->
<main style="padding-bottom: 88px">…</main>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-scrimThe backdrop, shared with the dialog and drawer
--fl-surfaceThe sheet fill
--fl-borderThe 1px border
--fl-radius-lgThe top corner radius (8px)
--fl-sheet-max-hThe initial height cap (50dvh)
--fl-option-hRow height (56px inside sheets, 48px dialogs)
--fl-z-sheetStandard sheet layer (below the snackbar)
--fl-dur / --fl-easeOpen/close animation timing
 
:root {
  --fl-radius-lg: 16px;           /* rounder sheet top corners */
  --fl-scrim: rgb(0 0 0 / 0.4);   /* darker scrim, every scrim follows */
  --fl-sheet-max-h: 60dvh;        /* taller initial cap */
}
