Bottom sheet

A sheet docked to the bottom edge on the native <dialog> — same overlay layer as the dialog, different presentation.

Usage

A bottom sheet presents choices or a compact task in the context the user is already in — it rises from the bottom edge, keeps that context visible behind a scrim, and returns as soon as the choice is made.

Do use it for

  • Choosing from a set — sort order, account picker, "add to" destinations. The canonical sheet is a vertical option list.
  • Compact forms — "new label", quick compose, a filter with two or three controls.
  • Details that shouldn't navigate — long metadata or an "about" panel that belongs to the current screen.

Don't use it for

  • Destructive or blocking decisions — "delete everything?" is a dialog territory; a sheet implies "this is still the same task".
  • Full-screen forms — real compose and settings sub-pages are the dialog's --fullscreen type.
  • Feedback — "Message sent" is a snackbar, never a sheet.

The handle is a glyph, not a gesture

The drag handle is drawn (32×4px, static). Drag-to-dismiss is not supported and not claimed — sheets close on scrim tap, Escape or their own actions, like every other overlay here. On desktop (≥600px) the sheet becomes a 560px card docked to the bottom edge instead of a full-bleed tray.

Dialog component

Anatomy

  1. Handle — the static 32×4 glyph; decorative (aria-hidden), no drag behavior.
  2. Title — short, 16px/500; optional for pure option lists where the rows are self-describing.
  3. Body — option rows, fields or long content; scrolls while the title stays pinned. Option rows reuse the dialog family's fl-dialog__option (48px, state layer).
  4. Actions — right-aligned, same button idiom as the dialog; often unnecessary for pure pick-one lists.

Behavior

  • Same overlay contract as the dialog: data-fl-open="sheet-id" opens it, data-fl-close inside closes it, and <form method="dialog"> records the pressed row or button in dialog.returnValue — picking "Unread first" from the sort sheet returns "unread" with zero JavaScript.
  • Dismissal: Escape and scrim clicks close it (native <dialog>); focus returns to the invoker on every close path. As with the dialog: if the body scrolls, Chromium may focus the scroll region first — set autofocus on the control that should receive initial focus (the demos do).
  • Scroll: the body scrolls inside the surface (capped at min(86vh, 640px)); handle and title stay pinned.
  • Responsive width: full-bleed below 600px; a 560px bottom-docked card above.
  • Stacking: a dialog can open over the sheet — the top layer stacks in DOM order and Escape peels only the top one.
  • Scroll lock: the page locks while any overlay is open — one CSS rule shared across dialog, sheet and drawer.
  • Animation: slides up on open, fades out on close — CSS only, prefers-reduced-motion disables it.
  • No-JS fallback (honest): without flint.js the sheet stays hidden and the page keeps working. Call showModal() yourself with one line, or drive it from your own code. See the overlay infra demo for the raw lifecycle.

Accessibility

  • Give the sheet aria-labelledby pointing at its title (skip this only when there is deliberately no title and the rows are self-describing).
  • The handle is decorative — mark it aria-hidden="true" so screen readers don't announce a "drag" affordance that doesn't exist.
  • Option rows are real <button>s or <label>+input pairs — native focus, native activation, no tabindex games.
  • The inert background is native: nothing behind the sheet is focusable or announced while it's open.
  • Don't remove the focus ring; the global :focus-visible ring is what makes the modal boundary visible to keyboard users.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

Option-list sheet — one method="dialog" form wraps the rows; picking one closes and records its value:

<button class="fl-btn" data-fl-open="sheet-sort">Sort conversations</button>

<dialog class="fl-sheet" id="sheet-sort" aria-labelledby="sheet-sort-t">
  <div class="fl-sheet__surface">
    <div class="fl-sheet__handle" aria-hidden="true"></div>
    <h2 class="fl-sheet__title" id="sheet-sort-t">Sort conversations</h2>
    <div class="fl-sheet__body">
      <div class="fl-dialog__list">
        <form method="dialog">
          <button class="fl-dialog__option" value="date" autofocus>Date received</button>
        </form>
        <form method="dialog">
          <button class="fl-dialog__option" value="unread">Unread first</button>
        </form>
      </div>
    </div>
    <div class="fl-sheet__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
    </div>
  </div>
</dialog>

Form sheet — fields in the scrollable body, actions pinned:

<dialog class="fl-sheet" id="sheet-label" aria-labelledby="sheet-label-t">
  <div class="fl-sheet__surface">
    <div class="fl-sheet__handle" aria-hidden="true"></div>
    <h2 class="fl-sheet__title" id="sheet-label-t">New label</h2>
    <form class="fl-sheet__body" method="dialog" id="label-form">
      <label class="fl-field">
        <span class="fl-field__label">Label name</span>
        <input class="fl-field__input" placeholder="e.g. Finance" autofocus>
      </label>
    </form>
    <div class="fl-sheet__actions">
      <button class="fl-btn fl-btn--text" data-fl-close>Cancel</button>
      <button class="fl-btn fl-btn--filled" form="label-form" value="create">Create</button>
    </div>
  </div>
</dialog>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-scrimThe backdrop, shared with the dialog and drawer
--fl-surfaceThe sheet fill
--fl-borderThe 1px border
--fl-radius-lgThe top corner radius (8px)
--fl-dividerThe drag-handle glyph
--fl-dur / --fl-easeOpen/close animation timing
 
:root {
  --fl-radius-lg: 16px;           /* rounder sheet top corners */
  --fl-scrim: rgb(0 0 0 / 0.4);   /* darker scrim, every overlay follows */
}
