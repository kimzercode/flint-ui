Side sheet

A supplementary surface anchored to the trailing edge — filters, metadata, focus flows. Standard as a persistent plain element on desktop, modal on the native <dialog> for mobile.

Usage

Side sheets are supplementary surfaces anchored to the left or right edge of the screen — M2's answer to "this content supports the screen, but isn't worth navigating to". Flint ships both M2 types:

Standard side sheet

Persistent and non-modal: no scrim, the page stays interactive. Use it for filters that control the primary content, supporting metadata panels (photo details, file info), or short configurations that stay on screen while the user works. Desktop and tablet only — M2 replaces it with the modal on mobile, and so does Flint (it is hidden below 600px).

Modal side sheet

Blocks the page behind a visible scrim and must be dismissed before the user can interact with the content again. On mobile it is the side sheet (M2's own rule); on larger screens it can focus attention on a key flow, such as a purchase or a filter-the-list moment.

Don't use it for

  • Blocking decisions — confirmation and alerts are dialog territory.
  • Primary navigation — that's the drawer or rail, and M2 explicitly pairs the side sheet on the opposite edge from the nav drawer so the two are never confused.
  • Feedback — snackbars, never sheets.
  • An inset floating panel — M2's Don't: fully insetting a side sheet from the edges makes its position and scroll behavior unclear while obscuring content. If it doesn't hug an edge, it's a card.

Bottom sheets become side sheets

When adapting for larger screens, M2 swaps bottom sheets for side sheets — same content contract, different edge. Both Flint variants share the same interior vocabulary, so the swap is a class change.

Bottom sheet component

Anatomy

  1. Header — title (16px/500) plus a close affordance. M2 recommends a separate close affordance inside the sheet even when the top bar toggles it.
  2. Content — one scroll region, vertical only. Option rows run full-bleed; labels and fields ride fl-sidesheet__group insets.
  3. Leading edge — the 1px border that stands in for M2's elevation. The surface hugs the trailing screen edge, square corners, full height (desktop).

Behavior

  • Two variants, one structure: the modal side sheet is a <dialog> (same platform roots as the dialog and bottom sheet: focus trap, inert background, Escape, top layer); the standard is any block element with fl-sidesheet--standard. Both share surface/header/body slots, so content moves between them unchanged.
  • Modal lifecycle: data-fl-open="id" opens it, data-fl-close in the header closes it, scrim tap closes it (a click on the transparent dialog element is the scrim click), Escape closes it, focus returns to the invoker on every path. The page is scroll-locked while open.
  • Standard lifecycle: visibility is author logic — toggle the hidden attribute (the demo does exactly that). No library JS is involved.
  • Scroll: vertical only — M2 explicitly forbids horizontal side-sheet scrolling, and the body slot scrolls while the header stays pinned (overscroll-behavior: contain keeps the page behind from rubber-banding).
  • Animation: slides in from the anchor edge on open — a transform swap, no new animation budget; prefers-reduced-motion disables it.
  • No-JS fallback (honest): the standard side sheet is plain CSS and works without JavaScript. The modal stays hidden without JS — call showModal() yourself or drive it from your own code, exactly like the dialog and bottom sheet.

Known gap: swipe-to-dismiss

M2 dismisses modal side sheets by swiping toward the anchor edge. Flint doesn't implement touch gestures (library contract): scrim tap, the header ✕ and Escape cover dismissal on every input.

Same gap on the bottom sheet

Placement

  • Trailing edge (right, in LTR): M2 pairs the side sheet on the opposite edge from the navigation drawer or rail — left nav, right sheet. Never both on the same edge.
  • Width: 320px, M2's desktop standard width — the --fl-sidesheet-w token.
  • Desktop modal: full height, flush to the edge, square corners.
  • Mobile modal (<600px): M2's modal specs — inset 48px from the top and 16px from the bottom, still flush to the anchor edge, width capped at 100vw - 48px so the page stays visible behind the scrim.
  • Standard sheet is desktop-only: below 600px it disappears (display: none) — on phones M2 swaps it for the modal variant. Give it a modal twin in your app logic.
  • Layering: the standard sheet sits at --fl-z-sheet, below the snackbar. The page needs padding-right clearance as wide as the sheet while it's open (the standard bottom sheet's padding-bottom lesson, mirrored).
  • Elevation, honestly: M2 gives standard sheets 8dp above content and modal sheets 16dp. Flint has no shadows: the leading-edge 1px border is the separation, and the modal's scrim is the blocking cue. The "above content" standard case is the same fixed panel; a truly grid-coplanar sheet (body shrinks to fit) is author layout — place it as a flex sibling instead of using the fixed class.

Contents

The interior mirrors the bottom sheet and dialog:

  • __header / __title — 64px header row (56px on mobile modal), title 16px/500, trailing close icon button.
  • __list — option rows, full-bleed, the shared 48px fl-option row. Checkboxes and radios compose exactly as in dialogs; whole-row checkbox toggles are <label class="fl-option">.
  • __group — inset wrapper for section labels (fl-section-label) and fields, so the rows can stay full-bleed without negative margins.
  • __body — the scroll region; everything above lives inside it.

Accessibility

  • Label the sheet: aria-label or aria-labelledby its title.
  • The modal is natively inert behind — nothing outside is focusable while it's open. The standard sheet is not inert; keep its content a state, not a task.
  • Option rows are real inputs — native focus and activation. The full-bleed rows draw the focus ring inside the row; don't remove it.
  • Checkbox state is announced natively (the tint would be presentation only — here rows stay untinted, M2's filter sheets don't tint).
  • Known gap: no swipe-to-dismiss and no back-gesture integration (see Behavior). All web dismissal paths work.

Modal side sheet — the M2 filter panel: checkbox rows as <label class="fl-option">, fields in __group wrappers:

<button class="fl-btn" data-fl-open="ss-filters">Filter files</button>

<dialog class="fl-sidesheet" id="ss-filters" aria-label="Filters">
  <div class="fl-sidesheet__surface">
    <header class="fl-sidesheet__header">
      <h2 class="fl-sidesheet__title">Filters</h2>
      <button class="fl-icon-btn" type="button" data-fl-close
              aria-label="Close filters">…</button>
    </header>
    <div class="fl-sidesheet__body">
      <p class="fl-sidesheet__group fl-section-label">Labels</p>
      <ul class="fl-sidesheet__list">
        <li><label class="fl-option">
          <input type="checkbox" class="fl-check"> Events
        </label></li>
        <li><label class="fl-option">
          <input type="checkbox" class="fl-check" checked> Personal
        </label></li>
      </ul>
      <div class="fl-sidesheet__group">
        <p class="fl-section-label">Format</p>
        <div class="fl-field">
          <div class="fl-field__box">
            <select class="fl-field__input" aria-label="File format">…</select>
          </div>
        </div>
      </div>
    </div>
  </div>
</dialog>

Standard side sheet — persistent, non-modal, zero library JS. Visibility is author logic (toggle hidden); the page clears the panel with padding-right:

<aside class="fl-sidesheet fl-sidesheet--standard" id="ss-details" hidden>
  <div class="fl-sidesheet__surface">
    <header class="fl-sidesheet__header">
      <h2 class="fl-sidesheet__title">Details</h2>
      <button class="fl-icon-btn" type="button" aria-label="Close details">…</button>

          </div>
        </div>
      </div>
      <ul class="fl-list">
        <li class="fl-list-item">…icon + metadata rows…</li>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-sidesheet-wSheet width (320px, M2's desktop standard)
--fl-scrimThe modal backdrop, shared with dialog/sheet/drawer
--fl-surface / --fl-borderSheet fill and leading-edge border
--fl-option-hRow height (48px)
--fl-z-sheetStandard sheet layer (below the snackbar)
--fl-dur / --fl-easeOpen/close animation timing
 
:root {
  --fl-sidesheet-w: 400px;        /* wider sheet on a wide layout */
  --fl-scrim: rgb(0 0 0 / 0.4);   /* darker scrim, every scrim follows */
}
