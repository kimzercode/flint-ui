Tabs

In-page tabs driven by a native radio group — fixed, icon or scrollable, with zero JavaScript.

Usage

Tabs switch between peer views of the same page — a note's overview, activity and settings. The bar stays put, the content below it changes, and exactly one panel is visible at a time.

Three things in Flint look like tabs. Pick by what the selected state means:

PatternSelected state meansUse for
.fl-tabs “this is the view I'm looking at” Peer content inside one page (this component)
.fl-tab-bar “this is where I am in the app” Top-level destinations pinned to the shell
.fl-chip “this is what I filtered / chose” A control that changes the content, not a view of it

Do use it when

  • The views are siblings — same object, different facets, and switching is cheap (no navigation, no data loss).
  • There are 2–4 of them; that is what fits as equal cells on a phone without truncating labels.
  • More than four labels exist but the set is ordered or labelled — use .fl-tabs--scroll, not a drawer.
  • The tab needs an icon plus a label for fast recognition (the 72px stacked bar), or the set is icon-only and space is tight.

Don't use it when

  • The views are sequential steps — that is a stepper, and “step 2 of 4” is not a tab.
  • Switching navigates (new URL, new screen) — use links; tabs are client-side views, and a bookmark cannot restore a radio choice.
  • There is one tab, or the “views” are really sections of one long document — use headings.
  • You want tabs to swipe — deliberately not shipped (see Behavior). Pin that content in place or use a carousel, not tabs.

Anatomy

The selected panel is the only one in the layout and the accessibility tree.

Inactive panel.

Disabled panel.

  1. Bar — 48px, one row, 1px divider underneath (--fl-divider). --fl-tabs-h changes the height; the 72px icon bar sets its own.
  2. Tab cell — a <label> wrapping the radio. Equal shares of the bar on phones; auto-width and centered from 905px.
  3. Indicator — a 2px bottom border in --fl-accent, on the selected cell only. It sits on the bar's divider line, not below it.
  4. Label — 14px, medium weight, all caps (--fl-tabs-transform), one line, ellipsized if the cell is too narrow.
  5. Icon — optional, 24px, stacked above the label. .fl-tabs--icons makes the bar 72px.
  6. Panels — one .fl-tabs__panel per tab, in the same order, inside .fl-tabs__panels.

Order is the contract

The k-th tab shows the k-th panel — that is how the mapping stays generic CSS with no per-instance IDs and no script. Reorder the tabs and you must reorder the panels; the cap is 8 tabs.

Behavior

State lives in the radio

Each cell wraps a real <input type="radio"> clipped to 1px, like chips. Clicking the cell, the label or the indicator checks that radio; the browser unchecks its siblings because they share a name. The bar and the panel change are pure CSS — zero JavaScript, zero resizing.

Keyboard is native

Tab reaches the selected radio (only one radio per group is tabbable). ←/→ move within the group and select as they go, exactly like a radio group everywhere else on the platform.

Fixed, icon, scrollable

  • Fixed (default) — cells share the bar equally. Use it for ≤4 short labels.
  • Icon — .fl-tabs--icons stacks a 24px icon above the label in a 72px bar. Icons are author content; the .fl-icon slot is a placeholder, not an icon set.
  • Scrollable — .fl-tabs--scroll keeps one row, gives each cell a 90px floor and lets the bar scroll natively with scroll-snap. The clipped tab is the affordance; no arrows, no script.

Phone, tablet, laptop

Up to 905px the bar fills its container: equal cells, which is the M2 fixed-tab look and the right one for a phone. From 905px the cells become auto-width and the group centers — M2's clustered tabs, and the reason a tab bar on a laptop does not stretch four words across 1200px. A scrollable set keeps starting at its first tab at every width.

Deliberately not shipped

  • Swipe between panels. M2 itself warns that tabs conflict with horizontally swipeable content, and a swipe that changes the view also fights the browser's back gesture. The bar is the control.
  • Dragging the strip to scroll, and the scrolling indicator choreography — native scrolling covers it.
  • Two-line labels, label resizing, mixed icon/no-icon sets — M2 marks all three as don'ts.
  • Nested tab bars, tabs below tabs, tabs attached to the bottom navigation.

One gap worth knowing

CSS cannot scroll a bar to a tab that gets selected from outside the bar. If your code checks a radio that is scrolled out of view (restoring saved state, deep-linking a view), also set bar.scrollLeft = item.offsetLeft — or call scrollIntoView({ inline: "nearest", block: "nearest" }).

Accessibility

  • It announces as a radio group, not a tablist. The control is the native radio, so the platform reports “Activity, radio button, 2 of 3, selected” and arrow keys work for free. Flint does not put role="tab" on a label that cannot take focus — that would be a lie the keyboard cannot back up.
  • Known gap: no WAI-ARIA tablist semantics. There is no aria-selected, no aria-controls, no Home/End. To help screen-reader users, give each panel a heading, and put the group's purpose in aria-label (or a fieldset/legend). The alternative — JS toggling ARIA and roving tabindex — is the one thing this component exists to avoid.
  • Hidden panels leave the page. Inactive panels are display:none: not reachable by Tab, not read aloud, and not in the accessibility tree. That is the correct behavior for a view switcher.
  • Focus ring on the cell. The ring is drawn on the label (inside it, so a scrolling bar cannot clip it) and follows :focus-visible — pointer clicks do not show it.
  • Touch targets. Every cell is at least 48px tall and as wide as its share of the bar; the indicator is decoration, the whole cell is the target.
  • Works without JS — and degrades without :has(). Switching is CSS plus native radios. On a pre-2023 engine without :has(), no tab can be singled out, so every panel is shown stacked and the bar stays a working radio group: content is never silently lost.

Code

Two files bring the library in; the toolbar itself is markup plus one checked radio per group.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<!-- Fixed tabs: radio group + panels in the same order.
     Give each group its own name on the radios. -->
<div class="fl-tabs">
  <div class="fl-tabs__bar" role="radiogroup" aria-label="Note view">
    <label class="fl-tabs__item">
      <input class="fl-tabs__input" type="radio" name="note-view" checked>
      <span class="fl-tabs__label">Overview</span>
    </label>
    <label class="fl-tabs__item">
      <input class="fl-tabs__input" type="radio" name="note-view">
      <span class="fl-tabs__label">Activity</span>
    </label>
    <label class="fl-tabs__item">
      <input class="fl-tabs__input" type="radio" name="note-view">
      <span class="fl-tabs__label">Settings</span>
    </label>
  </div>
  <div class="fl-tabs__panels">
    <div class="fl-tabs__panel"><!-- overview --></div>
    <div class="fl-tabs__panel"><!-- activity --></div>
    <div class="fl-tabs__panel"><!-- settings --></div>
  </div>
</div>
<!-- Icons: 24px slot above the label, 72px bar -->
<div class="fl-tabs fl-tabs--icons"> … </div>

<!-- More tabs than fit: one row, native scroll, 90px floor -->
<div class="fl-tabs fl-tabs--scroll"> … </div>

<!-- Icon-only tabs (allowed in scrollable sets) need a name on the input -->
<label class="fl-tabs__item">
  <input class="fl-tabs__input" type="radio" name="tools" aria-label="Checklist">
  <span class="fl-icon" aria-hidden="true"></span>
</label>

Set checked on exactly one radio per group — a group with none checked has no visible panel, because there is no view to show.

Theming

Everything is a CSS custom property — override inline or in your own stylesheet, no rebuild. --_-prefixed properties are internal state tokens and not part of the API.

TokenAffects
--fl-tabs-hBar height for text tabs (default 48px; icon tabs set 72px)
--fl-tabs-transformLabel case — uppercase by default (M2); none for Google's web-app sentence case
--fl-accentSelected label, indicator, focus ring
--fl-text-secondaryInactive label
--fl-dividerBar divider, pressed cell fill
--fl-hoverInactive cell hover fill
--fl-disabledDisabled label, muted indicator when the current tab is disabled
 
:root {
  --fl-tabs-transform: none;   /* sentence-case labels, Gmail-web style */
  --fl-accent: #188038;        /* indicator and selected label */
}

M2 sets tab labels in all caps. Google's own web apps moved to sentence case, so the case is a token rather than a hard-coded rule — the padding, weight and 14px size stay put either way.
