Rail shell

Bottom tab bar on phones that becomes a permanent 80px icon rail on desktop — same markup as the bottom-nav shell.

Usage

The rail shell is the middle ground between the bottom-nav shell and the drawer: on phones it is a standard bottom tab bar, and from 905px up the same element becomes a permanent 80px icon rail on the left edge.

Do use it when

  • You have 3–5 destinations that deserve permanent visibility on desktop, but a 280px drawer column is too much.
  • Your destinations are icon-shaped (Photos, Files, Music) — the rail is icon-only on desktop.
  • You want one nav element for both layouts — it literally reuses the bottom-nav markup.

Don't use it when

  • Destinations need visible text labels on desktop — the rail is icon-only there; use the drawer shell instead.
  • You have more than five destinations — nothing fits an 80px rail.
  • Desktop users need secondary nav sections or an account footer — that is drawer territory.

Compared to the other shells

Bottom-nav: same bar on both breakpoints. Rail: bar → icon rail. Drawer: hidden column → permanent 280px nav.

Drawer shell

Anatomy

  1. Top app bar — spans the full width, above both columns.
  2. Rail column (desktop) — fixed 80px, separated by a 1px right border, never a shadow.
  3. Rail items — stacked icon-over-label; the selected one is accent-colored only (no pill — the M2 2020 rail style).
  4. Content — the only scrolling area; capped by --fl-content-max.

On phones the rail column disappears and items 2–3 render as a normal bottom tab bar — same element, same classes.

Behavior

  • <905px: identical to the bottom-nav shell — fixed bottom bar, stacked icon-over-label tabs.
  • ≥905px: the bar moves into a left grid column: 80px wide, vertical, top-aligned, 1px right border, no top border.
  • No pills on desktop: unlike the bottom-nav's desktop bar, rail tabs opt out of the tinted pill — selection is accent color only, matching the M2 navigation-rail spec.
  • Selection: aria-current="page", reflected by flint.js inside [data-fl-nav]; works identically at both breakpoints.
  • Badges: absolute over the icon on desktop (there is no room beside it), inline everywhere else.
  • The rail is always visible on desktop — there is no collapsed/expanded state and no JS required for the layout switch.

Accessibility

  • The nav element carries aria-label="Primary"; it stays a single landmark at both breakpoints, so screen readers never see two navs.
  • Exactly one item carries aria-current="page".
  • Rail items are buttons or links with visible text labels — the 80px rail keeps the label, so nothing relies on title or tooltips.
  • Icons are aria-hidden; the label carries the meaning.
  • Include viewport-fit=cover in the meta viewport for safe-area support on phones.

Code

Two files bring the library in. The nav markup is exactly the bottom-nav shell's — only the wrapper class differs.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<body class="fl-reset">
<div class="fl-shell-rail">

  <header class="fl-top-bar">
    <h1 class="fl-top-bar__title">Flint Photos</h1>
    <button class="fl-icon-btn" aria-label="Search">
      <span class="fl-icon" aria-hidden="true"></span>
    </button>
  </header>

  <main class="fl-content">
    <p class="fl-section-label">Recent</p>
    <article class="fl-card">
      <h2 class="fl-card__title">Rail, not drawer</h2>
      <p class="fl-card__text">…</p>
    </article>
  </main>

  <!-- Mobile: bottom tab bar · ≥905px: icon rail (same element) -->
  <nav class="fl-tab-bar" data-fl-nav aria-label="Primary">
    <button class="fl-tab" aria-current="page">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Home</span>
    </button>
    <button class="fl-tab">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Library</span>
    </button>
    <button class="fl-tab">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Search</span>
    </button>
  </nav>

</div>
<script src="js/flint.js"></script>
</body>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-accentSelected rail item tint (icon + label)
--fl-borderRail's 1px right border
--fl-topbar-hTop bar height
--fl-tabbar-hBottom bar height on phones
--fl-content-maxMax content column width on desktop

The rail width (80px) is hard-coded in the desktop grid override — it is part of the component's proportions, not a token. If you need a different width, override .fl-shell-rail's grid and the tab padding.

:root {
  --fl-accent: #188038;
}
