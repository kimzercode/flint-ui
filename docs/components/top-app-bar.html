Top app bar

The bar that anchors every screen — navigation, title, actions, overflow — with the M2 scrolling behavior and the contextual action bar, on the platform's safe-area insets.

Usage

The top app bar displays information and actions relating to the current screen: branding, screen titles, navigation and actions. It sits at the top of every screen in the app and can transform into a contextual action bar when items are selected.

In Flint it is part of the shell: the first grid row of fl-shell, above the scrolling content. Below 600px it is 56px tall (M2's mobile spec); above, 64px.

Mobile-first, so some M2 variations are not here

Extended, prominent and dense bars, imagery in bars and iOS translucency are permanently discarded — native-feel apps on phones don't use them. The regular bar plus the contextual action bar cover what those apps actually do. See “Deliberately not in Flint” below.

The discard list

Anatomy

M2's recommended left-to-right placement, which the flex row gives you by just writing the elements in order:

  1. Navigation icon (optional) — a menu icon opening a drawer, an up arrow, or a back arrow; an fl-icon-btn at the far left.
  2. Title (optional) — fl-top-bar__title: the screen, the section or the app. It never wraps — long titles truncate. Left-aligned is the web/desktop idiom (M2's cross-platform note: iOS centers by default; that is a platform convention, not something Flint ships).
  3. Action items (optional) — fl-icon-btns, most-used on the left, progressing to the least-used.
  4. Overflow menu (optional) — the ⋮ at the far right; anything that doesn't fit goes here. It is a real menu.

Actions

  • Order by frequency: most-used action first (leftmost), overflow last (M2's icon-placement rule). Actions move into the overflow as the bar narrows — curate by hand, don't auto-collapse.
  • Icon-only actions need an aria-label ("Search", not the bare icon). The ⋮ is "More options".
  • Badges (unread counts) sit on the icon button — see the shell demo.

Transparent bar

Google's actual web apps (Keep, Drive) don't draw the bar as a filled strip: it sits on the page surface with no fill and no border, and the controls — the big rounded search pill — are the visual anchor. fl-top-bar--transparent is that pattern:

  • What changes: the fill and the 1px border go transparent (private tokens — two lines of CSS). Height, safe-area inset, layout and focus behavior are unchanged.
  • Deviation, recorded: M2 gives the top app bar its own surface. Flint follows Google's web apps instead — when everything is one surface, a bar border would fake separation the content doesn't have. This is not iOS translucency: nothing scrolls under the bar and nothing is blurred.
  • Search in the bar: the pill is a real fl-field wrapped in fl-top-bar__search — label-less input with an aria-label, 48px tall (M2's search bar height, via the scoped --fl-field-h token), fully rounded. The pill's own border is what anchors a transparent bar; without it the bar reads as a floating toolbar.
  • Contextual action bar still fills: even on a transparent bar, fl-top-bar--contextual takes the inverse-surface fill — a state change you can't see isn't a state change. The transparent variant only mutes the resting state.
  • Scroll-hide: works unchanged, and arguably looks better — a borderless bar slides away and leaves nothing behind.

This bar + the rail shell + a card grid + a dialog editor compose into the Keep-style app shell recipe — the web form factor Google Keep itself uses.

Scrolling

M2: scrolling upward hides the bar; scrolling downward reveals it. Add data-fl-scroll-hide to the bar and flint.js watches the shell's fl-content pane (or the window, for bars outside a shell), toggling is-hidden past a 4px threshold:

  • The bar slides up and the shell's bar row collapses — the content reclaims the space (no dead stripe left behind).
  • Scrolling up at any point reveals the bar; at the very top it always shows, even after a downward fling.
  • prefers-reduced-motion removes the slide.
  • No-JS fallback (honest): without flint.js the bar simply stays put — nothing hides, nothing breaks.

Deviation, recorded: M2 grows the bar's elevation when content scrolls behind it. Flint has no shadows, and the bar's 1px bottom border is already the constant separation — so there is nothing to switch on scroll.

Safe area: the bar pads itself with env(safe-area-inset-top), so an installed PWA under a status bar or a notch keeps its controls below it. Pair with viewport-fit=cover on the meta viewport. In a browser the inset is 0 and nothing changes.

Contextual action bar

When the user selects items (photos, messages, notes), the bar transforms: the fill recolors, the navigation icon becomes a close icon, the title reads "N selected", and the actions become the contextual ones. On close it transforms back.

Flint ships the state, not the state machine:

  • fl-top-bar--contextual recolors the bar to the inverse surface — the same mapping as the snackbar (--fl-text fill, --fl-surface text, light state layers on the dark fill).
  • The bar holds two fl-top-bar__group slot groups — the default one and the contextual one; exactly one is [hidden]. display: contents keeps the bar's flex as the single layout owner.
  • The swap is author logic (selection is app state — the same contract as the menu's aria-checked): one class and two hidden flips. The demo's script is four statements.
  • The contextual group stays in the DOM, so the swap works with JS off — whatever toggles it (a form control, a link, a checkbox) is author code.

Accessibility

  • The bar is a <header>; the title is a real heading (h1/h2 per document outline).
  • Every icon-only action carries a specific aria-label; "Notifications, 3 unread" beats a bare bell.
  • The overflow trigger uses aria-haspopup="menu" + aria-expanded — the menu contract.
  • Scroll-hide never removes the bar from the accessibility tree or the tab order — it is translated off-screen, so keyboard users still reach its actions; they are never trapped by scroll position.
  • Contextual bar: the close button's label is "Close selection", and the count text is a plain text node screen readers read as the title.

Deliberately not in Flint

M2 variationWhy not
Extended / prominent bar (128dp, larger title)Mobile-first native-feel apps don't use them; long titles truncate instead (M2's own "don't wrap in a regular bar" panel applies).
Dense / prominent dense (desktop only)Density variants contradict the 44px+ touch targets everywhere else in Flint.
Images in barsNeeds the prominent height to work and risks illegible text — M2's own "don't" panel shows the failure mode.
iOS translucencyM2 expresses bar separation with elevation; Flint's border is the separation. Translucency over scrolling content also fights the opaque surface contract. (The web-app need this covered — a bar that doesn't draw its own strip — is the transparent variant.)
Center-aligned titlesiOS platform convention — M2 itself says use the platform's default; the web default is left-aligned.

Code

The regular bar — anatomy in DOM order, the ⋮ wired to a real menu:

<header class="fl-top-bar">
  <button class="fl-icon-btn" type="button" aria-label="Open menu">
    <span class="fl-icon" aria-hidden="true"></span>  <!-- your nav icon -->
  </button>
  <h1 class="fl-top-bar__title">Flint Mail</h1>
  <button class="fl-icon-btn" type="button" aria-label="Search">
    <span class="fl-icon" aria-hidden="true"></span>
  </button>
  <button class="fl-icon-btn" type="button" popovertarget="bar-more"
          aria-haspopup="menu" aria-expanded="false" aria-label="More options">
    <span class="fl-icon" aria-hidden="true"></span>
  </button>
</header>

<div class="fl-menu" id="bar-more" popover aria-label="More options">
  <button class="fl-option" role="menuitem" type="button">Settings</button>
</div>

Scroll-hide — one attribute; flint.js toggles is-hidden:

<div class="fl-shell">
  <header class="fl-top-bar" data-fl-scroll-hide>
    <h1 class="fl-top-bar__title">Inbox</h1>
  </header>
  <main class="fl-content"><!-- scrolls --></main>
</div>

Transparent bar (Keep web) with the search pill:

<header class="fl-top-bar fl-top-bar--transparent">
  <button class="fl-icon-btn" type="button" aria-label="Open menu">…</button>
  <h1 class="fl-top-bar__title">Keep</h1>
  <div class="fl-field fl-top-bar__search">
    <div class="fl-field__box">
      <span class="fl-field__icon--leading fl-icon" aria-hidden="true"></span>
      <input class="fl-field__input" type="search"
             aria-label="Search your notes" placeholder="Search your notes">
    </div>
  </div>
  <button class="fl-icon-btn" type="button" popovertarget="bar-more"
          aria-haspopup="menu" aria-expanded="false" aria-label="More options">…</button>
</header>

Contextual action bar — two slot groups, one swap:

<header class="fl-top-bar" id="bar">
  <div class="fl-top-bar__group">
    <button class="fl-icon-btn" type="button" aria-label="Open menu">…</button>
    <h1 class="fl-top-bar__title">Photos</h1>
  </div>
  <div class="fl-top-bar__group" hidden>
    <button class="fl-icon-btn" type="button" aria-label="Close selection">…</button>
    <p class="fl-top-bar__title">1 selected</p>
    <button class="fl-icon-btn" type="button" aria-label="Delete selection">…</button>
  </div>
</header>

<script>
  // author logic — selection state is app state
  function setContextual(bar, on) {
    bar.classList.toggle("fl-top-bar--contextual", on);
    bar.querySelector(".fl-top-bar__group").hidden = on;
    bar.querySelectorAll(".fl-top-bar__group")[1].hidden = !on;
  }
</script>

Theming

The bar consumes the shared tokens — no top-bar-specific custom properties (internal --_ values are not theming API):

TokenAffects
--fl-topbar-hBar height (64px, 56px under 600px)
--fl-surface / --fl-borderBar fill and 1px bottom border (muted by the transparent variant)
--fl-field-hSearch pill height (scoped to 48px inside fl-top-bar__search)
--fl-text / --fl-surfaceContextual bar: inverse fill and its text color
--fl-fs-titleTitle size/weight
--fl-dur / --fl-easeScroll-hide slide timing
 
:root {
  --fl-topbar-h: 72px;   /* roomier bar */
}
