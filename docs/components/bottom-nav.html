Bottom-nav shell

App frame with a bottom tab bar — icon-over-label tabs on phones, inline pills in a centered bar on desktop.

Usage

The bottom-nav shell is the classic phone-first app frame: a top app bar, scrolling content, and a fixed bottom tab bar with 3–5 destinations. From 905px up, the same tabs become inline pills in a centered bar — no separate desktop navigation needed.

Do use it when

  • You have 3–5 top-level destinations — the sweet spot M2 recommends for bottom navigation.
  • The app is mobile-primary and destinations should be one thumb-tap away.
  • You want a FAB docked above the bar (the demo shows the pairing).

Don't use it when

  • There are more than five destinations — use the drawer or rail shell.
  • Destinations need labels longer than a word or two — pills stretch, but the bar caps them.
  • The page is a website rather than an app — tabs at the bottom read as mobile chrome, not web navigation.

Same markup, two layouts

The tab bar element is identical to the rail shell's — the shell class decides the desktop layout.

Rail shell

Anatomy

  1. Top app bar — icon buttons left/right, title center-left; height --fl-topbar-h.
  2. Content — the only scrolling area; capped by --fl-content-max on desktop.
  3. FAB (optional) — flat white, 1px border, no shadow; docks above the tab bar on mobile.
  4. Tab bar — fixed bottom on phones; ≥905px it becomes a centered pill bar. Selected tab is accent-colored via aria-current="page".

Behavior

  • <905px: the tab bar is fixed to the bottom; tabs stack icon over label, 12px labels.
  • ≥905px: the bar becomes an inline, centered 56px pill bar; the selected tab takes the tinted pill and stays inline (icon + label side by side).
  • Selection: aria-current="page" styles the active tab; flint.js moves it on click inside any [data-fl-nav] container — set it server-side and skip the JS if you prefer.
  • Badges: fl-badge rides the tab's icon (top-right); in the app bar it floats over the icon button.
  • FAB docks above the bar on mobile and moves with the content column on desktop.
  • Tabs can be links or buttons — anchors still navigate; the selection state is reflected either way.

Accessibility

  • The tab bar is a <nav> with aria-label="Primary" — not role="tablist"; these are navigation destinations, not view tabs.
  • Exactly one tab carries aria-current="page"; don't leave it off "so nothing is selected" — screen readers use it to orient.
  • Icon-only controls (FAB, app-bar buttons) need aria-label; labels and badges are visible text where they exist.
  • Badges are aria-hidden with the count duplicated in the button's label ("Notifications, 3 unread") — the visible "3" alone isn't announced.
  • Include viewport-fit=cover in the meta viewport so the bar respects safe-area insets.

Code

Two files bring the library in; the markup below is the whole shell.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<body class="fl-reset">
<div class="fl-shell">

  <header class="fl-top-bar">
    <button class="fl-icon-btn" aria-label="Open menu">
      <span class="fl-icon" aria-hidden="true"></span>
    </button>
    <h1 class="fl-top-bar__title">Flint Mail</h1>
    <button class="fl-icon-btn" aria-label="Notifications, 3 unread">
      <span class="fl-icon" aria-hidden="true"></span>
      <span class="fl-badge" aria-hidden="true">3</span>
    </button>
  </header>

  <main class="fl-content">
    <p class="fl-section-label">Today</p>
    <article class="fl-card">
      <h2 class="fl-card__title">Design review moved to 15:00</h2>
      <p class="fl-card__text">…</p>
    </article>
  </main>

  <button class="fl-fab" aria-label="Compose">
    <span class="fl-icon" aria-hidden="true"></span>
  </button>

  <nav class="fl-tab-bar" data-fl-nav aria-label="Primary">
    <button class="fl-tab" aria-current="page">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Home</span>
    </button>
    <button class="fl-tab">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Mail</span>
    </button>
    <button class="fl-tab">
      <span class="fl-tab__icon"><span class="fl-icon" aria-hidden="true"></span></span>
      <span class="fl-tab__label">Calendar</span>
      <span class="fl-badge" aria-hidden="true">3</span>
    </button>
  </nav>

</div>
<script src="js/flint.js"></script>
</body>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-accentSelected tab icon/label tint, pill text
--fl-tintDesktop selected-tab pill fill
--fl-hoverTab hover fill (mobile)
--fl-borderBar top border, FAB border
--fl-topbar-hTop bar height
--fl-content-maxMax content column width on desktop
--fl-tabbar-hTab bar height (56px at every breakpoint)
 
:root {
  --fl-accent: #188038;    /* green Google */
  --fl-tint: #e6f4ea;
}
