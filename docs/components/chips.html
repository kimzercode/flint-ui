Chips

Compact pills for filters, single choices, actions and tags — native inputs and buttons, zero JavaScript.

Usage

A chip is a compact, dynamic affordance: it appears next to the content it acts on, does one small thing, and can change state without a save button. That is the difference from a button, which is persistent and consistent across screens.

Do use it when

  • You are filtering a collection — the M2 placement is directly above or below the thing being filtered (a table, a list).
  • The user picks one of 2–5 visible options faster than a select would allow (choice chips).
  • An action is contextual to the content beside it ("Add reminder" on a note), not a standing toolbar.
  • You are showing an entity or tag the user entered (input chips — a person, a label, a place).

Don't use it when

  • The chip navigates to another screen — that is a link or a tab, and its selected state means "where am I", not "what did I choose".
  • The set has one option — a filter or choice with a single chip is a pointless control; M2 lists this as a don't.
  • You need a primary submit action — use a fl-btn; chips are secondary by nature.
  • The set is long and unordered — more than a screenful of choices is a select or a side-sheet filter list, not a chip wall.

Types

Four kinds, and the element is the contract — the same base class, a different native control underneath. Pick by semantics, not by looks:

KindElementStateTypical use
Filter label + <input type="checkbox"> many selected Labels/amenities above a list or table; add the fl-chip__check slot
Choice label + <input type="radio"> one selected (shared name) Sort order, size, density — 2–5 options
Action <button class="fl-chip"> pressed only Contextual command under content ("Add reminder")
Input (tag) span + fl-chip__remove presence Showing already-entered tags, with a remove button

Filter and choice chips contain a real input, so keyboard, form payload and screen-reader announcements are the platform's — not a role="button" imitation. Action chips are real buttons. Tags are static text plus one real button.

Input chips are display-only

M2's input chip can also be an editor: typing text transforms into a chip, chips reorder by drag, and a chip can expand into a details overlay. Flint ships the tag form (thumbnail + text + remove) and leaves the editor to the app: a text field plus chips is the honest web composition.

Anatomy

P Portland
  1. Container — 32px tall, one line, never wraps or resizes. --fl-chip-radius is a pill by default (M2: 16dp on a 32dp chip).
  2. Thumbnail (optional) — .fl-avatar--xs (24px) for a person, or an 18px .fl-icon for a place/thing.
  3. Text — 14px, one line, sentence case. Truncate the content, never the chip's shape.
  4. Check (filter only) — the fl-chip__check slot, revealed only while selected.
  5. Remove (input only) — a 24px button with its own aria-label; the × is drawn by CSS.

The 32px chip is below the 48px touch minimum, so the set pays for it: .fl-chip-set adds 8px above and below and 16px between rows, which makes every chip a 48px target without growing the chip.

Behavior

State lives in the input

The chip is a label; the checkbox or radio inside owns the state. The selected treatment is a token assignment keyed off :has(.fl-chip__input:checked) — so clicking the text, the check or anywhere else on the pill toggles the same control, and the native keyboard model applies: Space toggles a filter, arrow keys move through a choice group.

Selection changes width

A selected filter chip reveals its check slot, which adds 18px plus the 4px gap — the chip grows. That is the M2 behavior; don't reserve the space or shrink the label to compensate, and never resize the text.

Overflow is native scroll

When a set cannot wrap, use .fl-chip-set--scroll: one row, horizontal native scrolling with scroll-snap, no arrows and no JavaScript. The half-visible chip at the trailing edge is the "there is more" affordance — M2's scrollable-set guidance, minus a script.

Removing a tag is app code

The library ships the button, not the data model. Four lines of delegated author code are the whole handler:

document.addEventListener("click", (event) => {
  const remove = event.target.closest(".fl-chip__remove");
  if (remove) remove.closest(".fl-chip").remove();
});

Deliberately not shipped

  • Drag to reorder chips between fields — pointer choreography with no keyboard equivalent; M2 documents it, the web doesn't need it for tags.
  • Text-to-chip transform and expandable chips — an editor surface, not a primitive (see the input-chip callout).
  • Swipe gestures of any kind — a chip is a tap target.

Accessibility

  • The input is the control. It is clipped to 1px, not display:none, so it stays tabbable and in the accessibility tree; the label supplies the accessible name ("Personal, checkbox, not checked").
  • Focus ring on the chip. The global ring would land on the 1px input; :has(:focus-visible) moves it to the pill instead.
  • Name the set. Wrap filters in role="group" with an aria-label ("Filter notes by label") and choices in role="radiogroup"; a fieldset/legend pair works too.
  • The check is decoration. It is aria-hidden; the checked state is already announced by the input.
  • The remove button is a button. Give it aria-label="Remove Portland" — "Remove" alone leaves the target ambiguous when several tags are read in sequence.
  • Touch target. 48px effective via the set's spacing (see Anatomy). The remove button's own box is 24px — the smallest target in the library, and the one place a miss is recoverable (removing is not destructive to data beyond the tag).
  • Works without JS. Toggling, the tint and the check are CSS + native inputs; the tint needs :has() (baseline 2023) — without it, the chip is simply not tinted, the state is still announced by the control. Removing tags needs the author handler above.

Code

Two files bring the library in; below is one of each chip kind.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<!-- Filter chips: checkbox owns the state, the check slot shows selection -->
<div class="fl-chip-set" role="group" aria-label="Filter notes by label">
  <label class="fl-chip">
    <input type="checkbox" class="fl-chip__input" checked>
    <span class="fl-chip__check" aria-hidden="true"></span>
    Work
  </label>
  <label class="fl-chip">
    <input type="checkbox" class="fl-chip__input">
    <span class="fl-chip__check" aria-hidden="true"></span>
    Personal
  </label>
</div>
<!-- Choice chips: radios with a shared name = one answer -->
<div class="fl-chip-set" role="radiogroup" aria-label="Sort notes by">
  <label class="fl-chip">
    <input type="radio" class="fl-chip__input" name="sort" checked>
    Last modified
  </label>
  <label class="fl-chip">
    <input type="radio" class="fl-chip__input" name="sort">
    Title
  </label>
</div>
<!-- Action chip: a real button with a leading icon -->
<button class="fl-chip" type="button">
  <span class="fl-icon" aria-hidden="true"></span>
  Add reminder
</button>

<!-- Outlined variant: transparent container, 1px border -->
<button class="fl-chip fl-chip--outline" type="button">Set alarm</button>
<!-- Input chip (tag): thumbnail + text + a real remove button -->
<span class="fl-chip fl-chip--input">
  <span class="fl-avatar fl-avatar--xs" aria-hidden="true">P</span>
  Portland
  <button class="fl-chip__remove" type="button" aria-label="Remove Portland"></button>
</span>
<!-- Overflow: one row + native scrolling; no arrows, no JS -->
<div class="fl-chip-set fl-chip-set--scroll" role="group" aria-label="Neighborhoods">
  <label class="fl-chip"><input type="checkbox" class="fl-chip__input"><span class="fl-chip__check" aria-hidden="true"></span>Sørenga</label>
  <label class="fl-chip"><input type="checkbox" class="fl-chip__input"><span class="fl-chip__check" aria-hidden="true"></span>Bygdøy</label>
  <label class="fl-chip"><input type="checkbox" class="fl-chip__input"><span class="fl-chip__check" aria-hidden="true"></span>Rodeløkka</label>
</div>

Theming

Everything is a CSS custom property — override inline or in your own stylesheet, no rebuild. --_-prefixed properties are internal state tokens and not part of the API.

TokenAffects
--fl-chip-hChip height (default 32px; the set's spacing keeps the 48px target)
--fl-chip-radiusShape — pill by default; 8px gives the M3 boxy chip, 4px Shrine-like, 0 a cut chip
--fl-accentSelected text, check glyph, focus ring
--fl-tintSelected fill
--fl-dividerFilled (unselected) container
--fl-borderOutlined container border, filled hover/active
--fl-hoverOutlined hover, disabled fill
--fl-disabledDisabled text
--fl-icon-ph / --fl-text-secondaryAvatar fill and initials
 
:root {
  --fl-chip-radius: 8px;   /* M3's boxy chip — the pill is the M2 default */
  --fl-accent: #188038;    /* selection follows the brand */
  --fl-tint: #e6f4ea;
}

The shape note is worth repeating: M2 chips are pills (16dp on 32dp) and Material 3 made them boxier with 8dp corners. Flint follows the M2 idiom and ships the radius as a token, so the M3 look is one line away.
