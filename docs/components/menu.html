Menu

A dropdown of choices anchored to a button (the ⋮) — anchored, flipped and keyboard-navigated on the native Popover API; flint.js only positions it.

Usage

A menu displays a list of choices on a temporary surface. It appears when the user interacts with a button, action or other control — the classic trigger is the ⋮ overflow icon on a top bar or a list row.

Do use it for

  • Overflow actions — the secondary actions that don't fit on a bar or row (most-used actions stay visible, the rest go in the menu).
  • Compact choices — picking one of a few options without committing a form row to it.
  • Contextual commands — actions for the item the trigger belongs to (duplicate, share, remove).

Don't use it for

  • Blocking decisions — that is a dialog; menus never demand an answer.
  • Long or grouped content — settings panes, filters with many fields. That is a bottom sheet — M2 itself names it the mobile replacement for inline menus.
  • Selection inside a form — a form-bound choice is a select; that covers M2's exposed dropdown menu (the variation that shows the current selection above the list).

The hard parts are platform work — by design

The menu is a native popover: tap-outside dismiss, Escape, one-menu-at-a-time and top-layer stacking come from the browser. No scrim (M2 menus aren't modal — they simply render above everything), no z-index juggling. flint.js adds only anchoring, aria-expanded sync and the arrow-key pattern.

Dialog

Types

TypeShapeUse it for
Dropdown menu Anchor + popover panel; rows are fl-option buttons with role="menuitem" The ⋮ overflow — secondary actions on bars, cards and list rows
Text + icon list Rows with a leading icon slot; optional fl-option__meta for keyboard commands (⌘X) Row and card menus where icons aid scanning (M2 anatomy)
Selection-state list Rows as role="menuitemradio" with aria-checked; the check glyph draws in CSS, all radio rows share a leading gutter Single-choice menus (line spacing, sort order)
Exposed dropdown Not this component — M2's variation that displays the current selection above the list is the select in Flint.

Deliberately not in Flint: cascading (sub)menus — desktop-only in M2 and a nesting depth apps rarely need; a second level is better modeled as an item that opens a dialog or navigates. Dense menus follow the same rule as the top bar's dense variants.

Anatomy

M2's text list, text-and-icon list, and text-with-selection-state list are all one structure — the panel plus the shared option row:

  1. Panel — fl-menu[popover]: surface, 1px border, 4px radius, 180–280px width. Scrollable menus cap at the viewport height and keep their scrollbar.
  2. Rows — fl-option buttons (48px, hover state layer, full-bleed focus ring) with role="menuitem".
  3. Leading icon — your SVG or a fl-icon placeholder inside the row.
  4. Meta column — fl-option__meta: right-aligned keyboard commands, secondary color.
  5. Divider — a plain <hr> between unrelated groups.
  6. Selection check — drawn by CSS on [aria-checked="true"]; radio rows reserve the leading gutter so checked text keeps the column of its unchecked siblings.

Behavior

  • Markup contract: the trigger is a <button type="button" popovertarget="menu-id" aria-haspopup="menu">; the panel is <div class="fl-menu" id="menu-id" popover>. Opening is a platform attribute — no data-fl-* hook.
  • Positioning: the panel anchors below the trigger's left edge and flips when it would clip — right edge first, then above the trigger (M2: menus open downward at the top of the screen, adapt to the edges elsewhere). flint.js repositions on scroll and resize while open. Without flint.js the panel opens centered — usable, just unanchored.
  • Dismissal: click outside (light dismiss), Escape, selecting an item (author closes with menu.hidePopover() in the row's handler), or Tab. Focus returns to the trigger on every path.
  • Keyboard: ↑/↓ cycle rows, Home/End jump, Enter/Space activate (native button semantics), Escape closes, Tab closes — menus are not tab stops (WAI-ARIA).
  • Disabled rows: shown with disabled, not removed — M2: display actions as disabled when they can only be used sometimes. flint.js skips them in the arrow cycle.
  • One at a time: opening a menu closes any other open one — native popover light-dismiss semantics.
  • Animation: a 150ms fade (M2's transition for menus) via @starting-style; prefers-reduced-motion disables it.
  • No-JS fallback (honest): popovertarget opens the panel without flint.js (centered, unanchored). Browsers without the Popover API keep menus closed — dialogs and sheets (native <dialog>) cover the critical flows. aria-expanded needs flint.js or author code; set it yourself in server-rendered apps that skip flint.js.

Accessibility

  • Trigger: aria-haspopup="menu" + aria-expanded (synced by flint.js) and a real aria-label when icon-only ("More options"), never the bare ⋮.
  • Panel: role stays native popover — give the panel an aria-label ("Note actions") instead of role="menu" on the popover element itself; rows carry the menu semantics.
  • Rows are real <button>s: name, state and disabled are announced natively; selection rows use aria-checked (menuitemradio), not visual state alone.
  • Keep row labels short — a menu is scanned, not read (M2: scannable).

Known gaps

  • Contextual menu (long-press / right-click at tap point): CSS can't gesture and a long-press timer isn't in the JS budget — the same honest gap as the mobile tooltip trigger. Right-click menus are the browser's own; Flint menus are for consistent triggers.
  • Cascading menus: deliberately not shipped (see Types).
  • Popover API support: evergreen browsers only (Chrome/Edge 114+, Safari 17+, Firefox 125+); older engines get closed menus. This is the one Flint component whose no-JS fallback depends on the platform feature, not just on flint.js.

Code

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>

The ⋮ overflow menu — text rows, a group divider, instant dismiss on selection (author code closes the panel):

<button class="fl-icon-btn" type="button" popovertarget="m-more"
        aria-haspopup="menu" aria-expanded="false" aria-label="More options">
  <span class="fl-icon" aria-hidden="true"></span>  <!-- your ⋮ icon -->
</button>

<div class="fl-menu" id="m-more" popover aria-label="More options">
  <button class="fl-option" role="menuitem" type="button">Refresh</button>
  <button class="fl-option" role="menuitem" type="button">Settings</button>
  <hr>
  <button class="fl-option" role="menuitem" type="button">Sign out</button>
</div>

<script>
  // author code — menus dismiss instantly when an option is chosen (M2)
  document.getElementById("m-more").addEventListener("click", (e) => {
    const item = e.target.closest("[role='menuitem']");
    if (item) e.currentTarget.hidePopover();
  });
</script>

Text + icon rows and keyboard commands:

<div class="fl-menu" id="m-actions" popover aria-label="Note actions">
  <button class="fl-option" role="menuitem" type="button">
    <svg width="18" height="18" viewBox="0 0 24 24"><!-- your icon --></svg>
    Preview
  </button>
  <button class="fl-option" role="menuitem" type="button" disabled>
    Copy <span class="fl-option__meta">⌘C</span>
  </button>
</div>

Selection state — the check draws from aria-checked; the update is author logic:

<div class="fl-menu" id="m-spacing" popover aria-label="Line spacing">
  <button class="fl-option" role="menuitemradio" type="button"
          aria-checked="false">Single</button>
  <button class="fl-option" role="menuitemradio" type="button"
          aria-checked="true">1.15</button>
</div>

<script>
  const menu = document.getElementById("m-spacing");
  menu.addEventListener("click", (e) => {
    const row = e.target.closest("[role='menuitemradio']");
    if (!row) return;
    menu.querySelectorAll("[aria-checked]").forEach(r =>
      r.setAttribute("aria-checked", r === row ? "true" : "false"));
    menu.hidePopover();
  });
</script>

Theming

The panel consumes the shared tokens — no menu-specific custom properties (internal --_ values are not theming API):

TokenAffects
--fl-surfaceThe panel fill
--fl-borderThe 1px panel border and group dividers
--fl-radiusCorner radius (4px)
--fl-text / --fl-text-secondaryRow labels and the meta column
--fl-hover / --fl-dividerRow hover and pressed fills (shared with all state layers)
--fl-dur / --fl-easeOpen/close fade timing
 
:root {
  --fl-radius: 8px;   /* rounder menus */
}
