Selection controls

Checkboxes, radios and switches — native inputs drawn flat with appearance:none, zero JavaScript.

Usage

The selection controls are native <input> elements with appearance:none — the CSS draws the 18px boxes, rings and the switch pill, the platform keeps the state machine, keyboard behavior and form semantics. Nothing about a form's payload changes when you adopt them.

Pick the right one

  • Checkbox — independent yes/no options, or a select-many list. Checking one never implies anything about the others.
  • Radio — exactly one choice from 2–5 visible options. Group them with a real fieldset/legend so screen readers announce what the group is about.
  • Switch — one setting that takes effect immediately (no Save button). Style-wise it is a checkbox with role="switch"; semantically it is still a boolean input.

Don't use them when

  • More than ~5 radio options — that is a select; visible radios don't scale.
  • The choice triggers navigation or a destructive action on toggle — switches commit instantly; don't point one at Delete.
  • You need a tri-state (checked/unchecked/indeterminate) parent checkbox — indeterminate is not styled in 0.3; nest checkboxes flat instead.

Anatomy

  1. Checkbox — 18px, 2px corner, 2px border in secondary text color; checked = --fl-accent fill with a surface-colored check.
  2. Radio — 18px circle; checked = accent 2px ring plus an accent dot drawn as a radial-gradient (stays themable — no hardcoded image color).
  3. Switch — 36×20 pill; off = --fl-disabled track with surface thumb, on = --fl-tint track with accent thumb — the M2 state pair without the thumb shadow.

Behavior

  • Classes are the whole API: fl-check, fl-radio, fl-switch go straight on the input. There is no required wrapper — pair with a <label> (wrapping or for/id) so the text toggles the control.
  • Switches are checkboxes underneath: keep type="checkbox" and add role="switch" for the announcement; the name fl-switch only changes the drawing.
  • Radios share a name — that is what makes them exclusive; wrap the group in fieldset/legend (the demos do) rather than a bare div.
  • Rows: flex with a 12px gap, control first, 14px text label second — same pattern in the demo; the controls are flex: 0 0 auto so they never squish.
  • Disabled is the native attribute: boxes/rings gray out to --fl-divider, checked glyphs keep their shape in --fl-disabled; the switch dims to M2-style 45% emphasis. Disabled controls are skipped by tab order.
  • Keyboard: Space toggles checkbox/switch, arrows move radio selection — all platform behavior, untested by us because the platform guarantees it.

Accessibility

  • Every control needs a real text label — icon-only toggles have no name; the wrapping-label pattern in the demos is the default.
  • Radio groups want a legend; without it, a screen reader announces "Team, radio button, 2 of 3" with no idea of what for.
  • role="switch" on the switch input gives assistive tech the right announcement while keeping native toggling.
  • State is drawn with fill/ring changes that also follow the global :focus-visible ring — never remove that outline.
  • Don't disable a checkbox to "explain" something — disabled inputs are unfocusable and unannounced; if the user must know why, use helper text or a non-interactive note.

Code

Two files bring the library in; the markup below covers the three controls and their states.

<link rel="stylesheet" href="css/flint.css">
<script src="js/flint.js" defer></script>
<!-- Checkbox (label wraps the input — click the text to toggle) -->
<label style="display:flex; gap:12px; align-items:center;">
  <input type="checkbox" class="fl-check">
  <span>Email me product updates</span>
</label>

<!-- Radio group: fieldset/legend + shared name -->
<fieldset style="border:0; padding:0; margin:0;">
  <legend>Plan</legend>
  <label style="display:flex; gap:12px; align-items:center;">
    <input type="radio" name="plan" class="fl-radio" checked>
    <span>Free</span>
  </label>
  <label style="display:flex; gap:12px; align-items:center;">
    <input type="radio" name="plan" class="fl-radio">
    <span>Team</span>
  </label>
</fieldset>

<!-- Switch: checkbox + role="switch" -->
<label style="display:flex; gap:12px; align-items:center;">
  <input type="checkbox" class="fl-switch" role="switch">
  <span>Compact density</span>
</label>

<!-- Disabled states are the native attribute -->
<input type="checkbox" class="fl-check" disabled>
<input type="checkbox" class="fl-check" checked disabled>
<input type="radio" name="x" class="fl-radio" disabled>
<input type="checkbox" class="fl-switch" role="switch" disabled>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-accentChecked fill, radio ring/dot, switch-on thumb
--fl-tintSwitch-on track
--fl-text-secondaryUnchecked border
--fl-disabledDisabled glyphs and the switch-off track
--fl-dividerDisabled borders
--fl-dur / --fl-easeSwitch slide and fill transitions
 
:root {
  --fl-accent: #188038;   /* check, radio dot and switch thumb follow */
  --fl-tint: #e6f4ea;     /* switch-on track follows */
}
