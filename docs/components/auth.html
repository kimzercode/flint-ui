Auth shell

Centered sign-in / sign-up card with label-wrapped fields — zero JavaScript, one breakpoint.

Usage

The auth shell is a one-purpose frame: a centered card on a plain page, nothing else. No app chrome — auth is a pre-app screen with nothing to navigate to, so there is no top bar and no nav. The card and its fields are part of the shell, not separate components.

Do use it when

  • Sign-in, sign-up, password reset, MFA challenge — any single form screen reached before the app shell.
  • You want the form to work without JS — it's a plain <form> posting anywhere you like.
  • Consistency with the app shells matters — same tokens, same flat borders.

Don't use it when

  • The screen has navigation or multiple destinations — use a real shell.
  • You need form controls beyond text inputs (selects, toggles) — the field styles cover inputs only; the planned 0.2 components extend this.
  • The flow is multi-step with progress indication — wrap your own step indicator inside the card.

Anatomy

  1. Card — max 400px, centered on a plain page, 1px border, generous padding; the only surface. No top bar, no nav — auth is a pre-app screen.
  2. Title + subtitle — "Sign in" plus one line of context; the card's h1 doubles as the page heading.
  3. Fields — fl-field: label above, bordered input; the label wraps the input so clicking it focuses.
  4. Action row — secondary link ("Create account") left, filled button right.

Behavior

  • Zero JS: no flint.js needed — the card is a real form; submit posts wherever the action says.
  • One breakpoint: the card is fluid and centers at every width; under 600px the card's side margins and padding shrink. No layout flip.
  • Field states: hover darkens the border, focus takes the accent border, invalid (native :invalid) is styled too — all in CSS.
  • Card width: capped at ~400px — long forms should split across screens, not widen the card.
  • No app chrome: no top bar, no nav, no JS — there is nothing to navigate to before authentication. After sign-in, hand off to a real shell (drawer, rail, or bottom-nav).
  • Branding: no logo slot by default — add your wordmark or an <img> above the title inside the card if you want one; it needs no library CSS.

Accessibility

  • Each field is a <label class="fl-field"> wrapping its input — the label association is structural, no for/id needed.
  • Use the right autocomplete tokens (email, current-password, new-password) — password managers and the HTML spec both expect them.
  • The card is a <form> and its title is the page's <h1> — with no app chrome there is no other heading, so the hierarchy starts right at "Sign in".
  • Errors: use native validation first (required, type); server errors should be announced with role="alert" text inside the card.
  • Focus order is natural (DOM order); :focus-visible gets the accent ring.

Code

Only the stylesheet is needed — the auth shell uses no JavaScript.

<link rel="stylesheet" href="css/flint.css">
<body class="fl-reset">
<div class="fl-shell-auth">

  <main class="fl-shell-auth__content">
    <form class="fl-auth-card" action="#" method="post">
      <h1 class="fl-auth-card__title">Sign in</h1>
      <p class="fl-auth-card__subtitle">Use your Flint account to continue.</p>

      <label class="fl-field">
        <span class="fl-field__label">Email</span>
        <input class="fl-field__input" type="email" name="email"
               autocomplete="email" required>
      </label>

      <label class="fl-field">
        <span class="fl-field__label">Password</span>
        <input class="fl-field__input" type="password" name="password"
               autocomplete="current-password" required>
      </label>

      <div style="margin-top:16px; text-align:right;">
        <a href="#">Forgot password?</a>
      </div>

      <div style="margin-top:24px; display:flex; justify-content:space-between;
                  align-items:center; gap:8px; flex-wrap:wrap;">
        <a href="#">Create account</a>
        <button class="fl-btn fl-btn--filled" type="submit">Sign in</button>
      </div>
    </form>
  </main>

</div>
</body>

Theming

Everything is a CSS custom property on :root — override inline or in your own stylesheet, no rebuild:

TokenAffects
--fl-accentFocus border on inputs, filled button, links
--fl-borderCard border, input borders
--fl-radiusInput corner radius
--fl-radius-cardCard corner radius
--fl-fontEverything text
 
:root {
  --fl-accent: #188038;
}
