# Docs chrome → library component requirements

The docs site is built with Flint. Anything the docs need that Flint doesn't
provide is logged here as a real component requirement (ROADMAP principle:
"docs needs … become real component requirements, not guesses"), instead of
growing bespoke docs CSS forever.

| Docs need | Current workaround | Future library item |
|---|---|---|
| Layout grid (`sidebar 280px + content`) for docs pages | `.docs-shell` grid in docs.css | A content-layout shell (`fl-shell-docs`?) when exact utility shell variants are solid |
| Docs sidebar with sticky column + current-page highlight | docs.css + `aria-current` pattern (already the library pattern) | Maybe ship the aria-current nav-row pattern as public API docs, no new CSS |
| Code snippet blocks with copy buttons | docs.css `.docs-snippet` + docs.js (step 3+) | Code block component if docs prove it's generally wanted |
| Callout/update card (M2 "MD3 is available" card) | docs.css `.docs-callout` | Candidate for a `fl-callout` in 0.4 feedback release |
| Docs sidebar on phones | **Reuses `.fl-drawer` + `.fl-scrim` + flint.js toggling as-is** (hamburger in the docs topbar, data-fl-drawer-open) | Proof the drawer component generalizes beyond app shells |
| Scrollspy TOC | docs-only JS | Docs-only forever, not a library component |
| Docs sidebar inner scrolling when the component list outgrows the viewport | none (list is short; sticky wrapper intentionally has no `overflow-y`) | M2-style scrolling sidebar if the index reaches ~20 entries |
| Button disabled state styling (was documented as a 0.1 gap) | ~~interim opacity workaround~~ **Resolved in 0.3**: `fl-btn:disabled` gets flat gray treatment per variant (`--fl-divider` fill/border, `--fl-disabled` label) |
| `:active` state for outline/text buttons (only filled had one) | ~~hover fill only~~ **Resolved in 0.3**: outline/text `:active` take `--fl-divider`, matching icon-btn's pressed depth |
| Whole-clickable card (feed items that navigate) | cards host controls; rows handle whole-target clicks | documented "link-cover" pattern or `a.fl-card` support |
| Docs needed field variants (error state, helper text, filled, textarea, disabled) to build real form pages | 0.1 had only the base outlined field | **Shipped in 0.3**: `fl-field__help`, `fl-field--error` + `aria-invalid` hook, `fl-field--filled`, `textarea.fl-field__input`, `:disabled` — plus the `--fl-error` token |
| Dialog demos need a destructive confirm idiom (error-colored action) | text buttons had no destructive treatment | **Shipped in 0.4**: `fl-btn--danger` — `--fl-error` label with the text-button state layer |
| Dialog docs need long-content behavior (scrollable body) without a second scrollbar | step-1 surface scrolled as one block | **Shipped in 0.4**: surface is a flex column — body scrolls (`fl-dialog__body`), title and actions pinned |
| Dialog docs need M2's four dialog types (alert, simple, confirmation, full-screen) | step 2 shipped only the alert shape | **Shipped in 0.4**: `fl-dialog__list`/`__option` (48px choice rows for simple + confirmation), `fl-dialog__actions--stacked` (confirm above dismissive), `fl-dialog--fullscreen` + `fl-dialog__header`; surface cap aligned to M2's 560dp |
| Dialog docs need non-dismissible dialogs (decisions, not information) | scrim click and Escape always closed | **Shipped in 0.4**: `data-fl-dismissible="false"` — scrim and Escape refused, explicit `data-fl-close`/`method="dialog"` actions still close |
| Bottom-sheet docs need option-row lists (the canonical sheet content) without a second row pattern | rows lived only in the dialog family | **Shipped in 0.4**: the row is promoted to `.fl-option` with `--fl-option-h` (48px dialogs, 56px sheets — both spec numbers, one row component) |
| Overlay docs had to explain Chromium focusing the scroll region first | first-focusable claim was engine-dependent | **Shipped in 0.4**: documented the scroll-container quirk; demos and snippets set `autofocus` on the intended control (the platform mechanism) |
| Snackbar demo needed a dark-surface action color (Google's bright blue on the inverse surface) | only the light-surface `--fl-accent` existed | **Shipped in 0.4**: `--fl-accent-inverse` (#8ab4f8) — the accent for text on dark/inverse fills |
| Undo and other snackbar actions need app semantics (what actually gets undone) | demo wires the click handler by hand | Intentionally author code — the library shows/times/hides; documented as the contract, not a gap |
| Apps with a persistent bottom nav need the snackbar above the tab bar | one-line override recipe in the docs | Shell modifier (`fl-snackbar--above-nav`?) only if the recipe proves commonly needed |
| Tooltip docs need WCAG 1.4.13 Escape dismissal (content on hover/focus must be dismissible) | CSS-only can't; the tooltip is supplementary (trigger keeps its own aria-label) so impact is low | One-line keydown recipe, or a library dismiss hook, if an audit demands it |
| M2's mobile tooltip trigger is long-press — CSS can't gesture | hover + focus only in 0.4, documented honestly; Android tap-focus often shows it via :focus-within | A few lines of author JS, or a `data-fl-tip` long-press handler in flint.js if asked for |
| Field docs need affixes, icons, a counter and a password toggle — real form pages need units in the box and reveal | 0.3 fields had label/help/error/filled only | **Shipped in 0.4**: `fl-field__box` owns the chrome (one structure for all fields), `__prefix`/`__suffix`/`__icon--leading/--trailing`, `__footer` + `__counter`, `data-fl-password-toggle` in flint.js, `fl-field__input--grow` |
| Field labels wrapping the whole field are invalid HTML once a trailing button exists, and helper text inside a label can leak into the accessible name | 0.3 used `<label class="fl-field">` wrapping input + help | **Resolved in 0.4**: labels are siblings with `for`; helper lives on `__footer`, outside the label — recorded as a deliberate contract change (the library is pre-production) |
| M2 floats the label into the border notch | static label above the field | **Permanent decision**: M2's own "independent label" pattern; better a11y (label never doubles as a placeholder) — documented on the Text fields page so it stops resurfacing |
| M2 shows the counter as `55/100` inside the box | the screenshots' in-box value is the grading-scale *suffix* example | Counter lives on the footer line bottom-right; in-box `55/100` is a suffix example, not a counter |
| M2's 48dp icon target doesn't fit a 44px field (48 lives in M2's 56dp field) | 44px-wide target at full inner height (42px) | Still above WCAG 2.5.8; documented instead of inflating the field |
| `field-sizing: content` auto-grow isn't in Firefox | opt-in modifier with a `rows` fallback | Ship the modifier now; document the fallback |
| M2 sheets have no drag handle | 0.4 pre-audit shipped a static 32×4 glyph the docs had to disclaim | **Removed in 0.4** (`bottom-sheets-docs/` audit): a control that signals a gesture that doesn't exist is a false affordance |
| M2 caps a modal sheet's initial height at 50% of the screen | pre-audit opened at `min(86vh, 640px)` — nearly full-screen menus | **Shipped in 0.4**: `--fl-sheet-max-h: 50dvh` (fallback 50vh; `--full` is the documented escape hatch for content that needs the screen) |
| M2 lists swipe-down as a sheet dismissal path | scrim, Escape, rows and close actions all work | **Not shipped**: a vertical drag has to arbitrate against the sheet's own scroll — a gesture that sometimes scrolls and sometimes closes is worse than none. Documented gap |
| Android's back gesture navigates away instead of closing a modal surface | all four web dismissal paths work | **Known gap**, 0.5 candidate: history-state + dialog stack. No 10-line shim in 0.4 |
| M2's expanding bottom sheet (collapsed pill ↔ full screen) | — | **Retired, not deferred**: on the web the collapsed state is a FAB/sticky action bar and the expanded state is `fl-dialog--fullscreen`; the only unique part is the morph state machine. Recorded so it stops resurfacing |
| M2 sheets label their menu rows 56dp, dialogs 48dp | one 48px row class owned by the dialog | **Shipped in 0.4**: the row is `.fl-option` with `--fl-option-h` set per surface — one row component, both spec numbers |
| Web apps share the window with the URL bar, home indicator and keyboard (an Android app owns its window) | tab bar + FAB handled safe areas; sheet actions and snackbar didn't; `vh` caps overhang the visible viewport; 24 `:hover` rules stick on tap | **Shipped in 0.4**: `env(safe-area-inset-bottom)` on sheet actions + snackbar, `dvh` viewport caps, `@media (hover: hover)` guards on every hover fill, `overscroll-behavior: contain` on scroll regions, `-webkit-tap-highlight-color: transparent` in the reset |
| M2 gives sheets/dialogs 16dp/8dp elevation | flat 1px borders everywhere | **Documented deviation**, unchanged: separation comes from borders, scrim and surface color |
| "Overlay" was never a Material component — the M2 component list has no slot for it | 0.4 planned an "overlays guide page" + `demos/overlay.html` | **Deleted in 0.4**: shared behavior lives on each component page with cross-links, as M2 does; the word is gone from CSS/JS/docs ("modal surface", "scrim", "containment") |
| The notes prototype (`prototype/test-mdl2.html`) hand-rolls a menu, scrim, snackbar host (with its own compositing bug), ripple, shadowed FAB and custom search — a mockup built freeform, without the library | none — it was never built with Flint | **0.5 decision (2026-11-16)**: rebuilt 100% on Flint components as the first `samples/` app; that rebuild is the version's acceptance gate. Per-app code is the notes array + undo only |
| Master-detail split view (Gmail desktop, Keep): list pane + detail pane | prototype hand-rolls two panes in one HTML file | **0.5**: split shell (list pane + detail pane ≥600px) as a shell recipe, plus **side sheet** (standard + modal) for supplementary panels beside content — the missing member of the sheet family (needs a `sheets-side-docs/` reference audit before building) |
| Top app bar: M2's extended/prominent/dense variants, images in bars, iOS translucency | `.fl-top-bar` ships only the regular bar as a shell part | **Discarded 2026-11-16 (permanent decision)**: mobile-first native-feel apps don't use them. What 0.5 adds instead: the bar promoted to a documented component (safe-area top inset, action ordering, scroll-hide, contextual action bar state), each discard recorded as "deliberately not in Flint" on its docs page |
| Top bar scroll-hide hides by collapsing the shell's bar row, which changes the scroll range — the browser clamps scrollTop mid-transition and those events flipped the state back | **Shipped in 0.5**: flint.js keeps a 300ms settle window after a toggle that only tracks position; the clamp lands exactly where the user's content would be (the bar's 64px of range became viewport), so the visual is seamless |
| M2 grows the bar's elevation when content scrolls behind it | **Deviation, 0.5**: the bar's 1px border is the constant separation — no conditional border/fill logic on scroll |
| The contextual action bar's slot swap (close replaces nav, title → "N selected") is app state | **0.5 contract**: the library ships the recolor (`fl-top-bar--contextual`, inverse surface — same mapping as the snackbar) and the two `fl-top-bar__group` slot groups; the toggle is four lines of author logic, like the menu's `aria-checked` |
| The menu's initial design used a scrim; M2 menus aren't modal | **Shipped in 0.5**: native Popover API light-dismiss instead — no scrim, no z-index token, one-menu-at-a-time from the platform (see `demos/menu.html`) |
| Notes app form factor: Gmail-desktop-style master-detail split (planned 0.5 step 3) | **Discarded as a component 2026-11-17** (user confirmed, refs `google-keep-gdrive-references/`): M2 has no spec for it; Google's own web apps are inconsistent (Gmail web = split, Keep/Drive web = overlay); Keep tablet dual-pane = two complete instances, each pane owning its own bar (device-native pattern). The half-version — layout without the selection/focus/back-stack contract — is not worth shipping under the Material name. **Returns in a later release** as an "App shells" guide/recipe composed from existing primitives (rail + panes + side sheet), sequenced after the side sheet ships, audited against user-supplied Gmail-web refs |
| Desktop form factor for the notes app | **Keep-web pattern** (2026-11-17): permanent side nav on desktop (`fl-shell-rail`), card grid, note editor as a centered dialog overlay (Keep web's actual editing surface) — the mobile-first library's desktop story, not a second pane |
| Google's web apps (Keep, Drive) show the top bar with no fill and no border of its own — the controls (search pill) are the anchor | **Shipped in 0.5**: `fl-top-bar--transparent` — documented deviation from M2's surfaced bar; contextual action bar always fills (inverse surface) so the state change stays visible |
| M2 side sheets: standard = 8dp above content, modal = 16dp elevation; side sheets have no shadow budget in Flint | **Shipped in 0.5**: the 1px leading-edge border is the separation (`css/flint.css` §18); the "above content" standard case is the same fixed panel — a truly grid-coplanar sheet (body shrinks to fit) is author layout. Modal blocking comes from the visible scrim, not elevation |
| M2 standard side sheets are tablet/desktop only (the modal replaces them on mobile) | **Shipped in 0.5**: `fl-sidesheet--standard` is `display: none` below 600px — documented on the Side sheet page; apps give it a modal twin |
| M2 dismisses modal side sheets with a swipe toward the anchor edge | **Gap, documented**: no touch gestures in the library (same contract as the bottom sheet) — scrim tap, header ✕ and Escape cover every input |
| M2 modal side sheet (mobile) insets 48dp top / 16dp bottom, flush to the anchor edge | **Shipped in 0.5**: media query on `dialog.fl-sidesheet[open]`; desktop is full-height flush |
| Recipes (card grid, empty state, Keep-web shell) are compositions, not components | **Shipped in 0.5**: `docs-site/src/recipes.njk` + `demos/recipe-keep.html` — author CSS is layout-only (grid + empty-state stack, ~10 lines total); the library gains no classes. Masonry documented as a deliberate gap (no engine ships `grid-template-rows: masonry`) |
| The ⋮ overflow menu has nothing to open — menu was deferred from 0.4 but never listed in the public 0.5 row | prototype hand-rolls menu + scrim + Esc | **0.5**: `fl-menu` (dropdown with scrim, Escape, instant dismiss on selection) |
| M2 chips are **pills** (16dp radius on a 32dp container); M3 made them boxier with 8dp corners | **Shipped in 0.5 as spec**: `--fl-chip-radius: 999px` (stays a pill at any height); `8px` gives the M3 look, `4px` the Shrine override, `0` the cut shape. The radius is a public token, not a `_` state token |
| M2 filter chips selected = neutral container + check; choice chips selected = primary container | **Deviation, 0.5**: both use Flint's tint/accent selection language (shared with nav and list selection); the `fl-chip__check` slot supplies M2's check affordance on filters. Recorded on the Chips page |
| Chips: M2 documents drag-to-reorder, text→chip transform, expandable chip and swipe gestures | **Discarded 2026-11-18**: pointer choreography with no keyboard equivalent, or an editor surface rather than a primitive. Input chips ship as display tags (thumbnail + text + remove); the editor is author composition (field + chips) |
| A 32dp chip is below the 48dp touch minimum | **Shipped in 0.5**: `.fl-chip-set` pays the target — 8px above/below and 16px between rows makes each chip a 48px target without growing it. The remove button's own box is 24px (smallest target in the library; recoverable action, documented) |
| M2 scrollable chip sets show arrows / offset the first chip | **Shipped in 0.5**: `.fl-chip-set--scroll` is native horizontal scroll + `scroll-snap` with the scrollbar hidden; the clipped trailing chip is the affordance — no arrows, no JS |
| Avatars have no M2 spec page (the 0.5 plan listed one) | **Shipped as a building block, 2026-11-18**: one `.fl-avatar` (40/32/24px, initials or `<img>`) shared by lists, chips and top bars; documented on the Lists page. Pre-production migration retired `.fl-list-item__avatar` in favor of the shared class |
| Tabs: M2 documents swipe-to-change-tab and swipe on the strip itself | **Discarded 2026-11-18 (permanent decision)**: M2's own guidance warns tabs conflict with horizontally swipeable content, a swipe also fights the browser's back gesture, and the bar is already the control. Tabs ship as a tap/click + arrow-key component |
| Tabs: the WAI-ARIA tab pattern wants `role="tab"`/`aria-selected`/`aria-controls`, roving tabindex and Home/End | **Deviation, 0.5**: the bar is a native radio group — "Activity, radio button, 2 of 3, selected" plus native arrow keys — because ARIA tab semantics need JS to stay truthful. No `role="tab"` on labels that cannot take focus. Gap documented on the Tabs page, with the panel-heading mitigation |
| Tabs: tab↔panel mapping with no per-instance IDs and no JS | **Shipped in 0.5**: document order is the API — the k-th tab shows the k-th panel via one 8-branch `:has()` rule; reordering tabs means reordering panels (documented). Cap 8 tabs |
| Tabs: a tab selected programmatically outside the bar is not scrolled into view | **CSS gap, documented**: the bar cannot know which cell is off-screen; authors restoring state set `scrollLeft`/`scrollIntoView`. Native keyboard use always has the selected cell in view |
| Tabs: M2 labels are all caps; Google's web apps use sentence case | **Shipped in 0.5 as a token**: `--fl-tabs-transform: uppercase` (M2 default), `none` for the web idiom — padding, 14px and 500 weight stay fixed either way |
| Tabs: M2 fixed tabs become a clustered, auto-width group on larger screens | **Shipped as match, 0.5**: equal cells below 905px, auto-width 120px-floor cells centered from 905px — the same breakpoint the shells use. A scrollable bar is pinned to `flex-start` at every width (centering overflow makes the left tabs unreachable) |
| Data table: M2 draws no vertical rules (and no horizontal scroll) | **Deviation, 0.5**: one 1px divider after the sticky selection column. With shadows banned, it is the only thing that keeps a horizontally scrolled row from reading as text cut mid-word; documented on the Data table page |
| Data table: M2 shows inline ⋮ menus, column/row drag, grouping, aggregates | **Discarded 2026-11-18**: data-grid territory — every one needs JS, and a trailing icon-button/menu in a cell covers the real use. Sticky header row deferred until a screen needs it |
| Data table phones: M2 reflows to a stacked card per record | **Not shipped as a second structure, 0.5**: one table that scrolls with a pinned selection column, plus a documented app recipe — the same records as two-line list rows below 600px. Two table structures would mean two state maps |
| Data table sorting/paging: no JS in the library | **Shipped in 0.5**: sort state is the author's `aria-sort` (button or `?sort=` link), paging is links (`?page=`) with `role="link" aria-disabled="true"` for unavailable directions; rows-per-page select needs a form or app handler (documented gap); select-all is a 10-line author snippet in the demo |
| Data table truncation: auto table layout ignores `max-width` on cells | **Documented mechanism, 0.5**: a column widens and the table scrolls; truncation is the explicit `.fl-data-table__truncate` slot with a capped width, and a truncated header wraps the sort control in `.fl-tip` for the full label |
| Data table touch targets: M2 48×48 for the checkbox | **Shipped in 0.5**: the selection cell is a label target (48px wide cell, 48px min height) so the 18px `.fl-check` is not the hit area. The header select-all is decorative without author wiring, documented |
